# 手厚い将棋の基準版：support10 / D10

2026-11-13採用。基本は位を支えて厚い将棋を目指す。支えが成立しないときは、低く構えて相手の攻めを誘い、別方面から反撃する選択肢も持たせたい。後者を実現する新しい評価項は未実装で、今後の改善課題とする。

## 使用するエンジン

GUIには `bin/teatsui-2026-11-13/rakuyou` を別エンジンとして登録する。起動場所にかかわらず専用ディレクトリへ移動して実行するランチャー。表示名は `Rakuyou support10 D10 2026-11-13`。既存GUIの登録内容は自動変更していない。

| 設定 | 採用版の既定値 |
| --- | --- |
| ExperimentalSupportChainBonus | 10（互換性のため旧名称を維持） |
| KingContactDeficitBonus | 10（新しいUSI項目） |
| ShinYonenagaGyoku | true |
| OwnBook | true |
| BookMaxPly | 20 |
| ShinBookFile | shin-yonenaga-book-v1.txt（既存の17局面） |

supportとDは0〜10で指定できる。設定は初回 `isready` より前に行い、比較するときは新しいプロセスを使う。旧実験用の `RAKUYOU_KING_CONTACT_DEFICIT_CP` 環境変数には依存しない。GUIに保存済みのsupport0がある場合は10へ設定する。

supportは五段目の歩・金銀２枚の限定的な支持関係への加点（進行度で減衰）。Dは玉の周囲８マスの敵の利き超過に対する減点。どちらも厚みや持続可能な守備の完全な判定ではない。相手の薄いところを攻めること、位の維持可能性、侵入駒が働くまでの時間などは引き続き局面全体で検討する。

## 旧版と実験の保全

旧 `bin/release`、元の `src/`、過去の実験バイナリ・データ・封印済み計画は変更していない。旧版へ戻すときはGUIで以前のエンジン登録を選ぶ。採用版は評価データを従来の `bin/` から参照するので、共通データを削除しない。

凍結された過去の比較を壊さないため、採用コードはこのディレクトリの `adoption.patch` と基底ハッシュで管理する。ルートで通常の `make release` を実行すると旧ソースのビルドになる。採用版を再ビルドするには、まだ存在しない出力先を指定する：

```sh
python3 adopted/support-contact-2026-11-13/build.py --output results/teatsui-baseline-rebuild
```

出力は指定先の `runtime/rakuyou`。基底ソースが変わっていれば停止するため、その際はパッチをレビューして更新する。旧版や採用済みバイナリを上書きしない。

## 検証と限界

130局面×４設定で静的評価が実験版と一致。２局面×４設定の深さ７探索で最善手・評価値・深さ・ノード数・読み筋が一致し、既定値10/10の２回も一致した。既存の差分評価・巻き戻し・先後反転検査を含むネイティブ診断を使用。別cwdからの起動と先後の新米長玉初手も確認。旧比較の257入力ハッシュを維持。

前回の三間／中飛車比較で両方あり4勝0敗、確認の四間／居飛車比較では1勝3敗（両方なしと同じ開始別勝敗）。少数の既知派生局面による開発検証で、棋力向上の証明ではない。ユーザーの棋風判断と基本採用の意向に基づく基準版であり、係数の微調整・新しい評価項・学習は行っていない。

詳細ログ・ソーススナップショット・ビルド記録・検証結果は `results/adopted-support-contact-2026-11-13/` に保存。
