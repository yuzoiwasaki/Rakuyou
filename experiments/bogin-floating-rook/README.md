# 棒銀に対する浮き飛車・3九玉の試験

早い▲4六歩・▲3六歩を省き、浮き飛車の横利きを残す。
玉は▲3八銀・▲4九金に支えられた▲3九玉型を目指す。
▲7八金は左側に残し、登録手順では▲2八玉へ進めない。
定跡離脱後の▲2八玉は、10局の図を見たユーザーが許容したため修正しない。

## 修正版を初手から20局試す

```sh
caffeinate -i python3 experiments/bogin-floating-rook/run_matches.py --startpos
```

修正版対通常Rakuyouを先後10局ずつ。結果は
`results/floating-rook-startpos20.json` に保存し、同じコマンドで再開できる。
深さ15上限・秒読み10秒・Threads1・Hash512MB・総256手上限。
試験側は専用定跡ON・BookMaxPly32、通常側は標準定跡ON・20手目まで
（エンジン既定の選択条件・ランダム選択）。初手の▲4八玉／△6二玉は維持する。
今回の追加定跡は先手用。後手10局は既存の指し方を確認する枠で、
浮き飛車の効果を先後合計の勝率から推定しない。

既存の専用定跡への命中と、今回追加・置換した局面への命中を分けて記録する。
追加局面は盤面・持駒・手番で識別し、手順前後にも対応する。
各局の `trial_book_hits` と先後別集計の `trial_book_games` を確認する。
通常定跡も実行時にコピーして固定する。途中局面からの10局とは合算しない。
開始前の動作確認は `--startpos --smoke`（20枠、各2手、別ファイル）。

実施結果は先手5勝4敗1未決着、後手2勝7敗1未決着。追加定跡の命中は0局。
先手6局は14△4二銀（登録の△7二銀と異なる）、残り4局は早い角交換へ分岐。
後手は追加定跡の対象外。記録された入力・定跡のハッシュは一致し、再開・エラーなし。
32手目までのネイティブSFEN照合でも追加局面との一致は0、保存済み定跡への
12局面の直接照会はすべて命中した。読み込み不良ではなく、対象形が出なかった。
この20局の勝敗を浮き飛車案の効果と解釈しない。未決着2局も同一SFEN4回はなく、
いずれも試験側の終盤評価は大幅なマイナスだが、集計上は未決着を維持する。
監査結果は `results/bogin-floating-rook/startpos20-audit.json`。

## 条件を限定した二つの手順

第11局の14手目△7二銀までを共通の入口にする。

- 交換を許された場合：▲2六歩 △8三銀 ▲2五歩 △8四銀 ▲2四歩
  △同歩 ▲同飛。△8五銀なら▲2三飛成とし、以後は通常探索へ戻す。
  先に△3二金と成りを防がれた場合は▲2六飛。△8五銀なら▲3八銀、
  続いて△4一玉なら▲3九玉と収める。
- △3三角の場合：▲2六歩 △8三銀 ▲2五歩 △3三角 ▲2六飛
  △7四銀 ▲3六飛 △2二銀 ▲3八銀 △6五銀 ▲3九玉。

▲3八銀・▲3九玉の登録は、先に△3二金とされた浮き飛車の分岐で引き続き使う。
これらの相手の応手は適用条件であり、実戦で必ず出現するわけではない。
未登録局面は通常探索に戻す。探索中の玉移動を禁止する実装はしていないため、
定跡を離れた後の▲2八玉や飛車の使い方は対局で確認する。

```sh
python3 experiments/bogin-floating-rook/prepare.py
```

正式版42局面を基に、12局面を追加・置換して試験版53局面を生成する。
置換するのは既存の `bogin-silver83-move17-ply17-4i5h` だけ
（▲5八金を▲2五歩に変更）。後手の定跡や他の既存登録は維持する。
保留中の角転換案は混ぜない。

生成先は `results/bogin-floating-rook/` の `baseline-book.txt` と
`candidate-book.txt`。両側ともBookMaxPly32で使用する。

全登録手の合法性と命中、手順前後での合流、早い△8六歩への探索復帰、
OwnBook OFFでの抑止をネイティブエンジンで確認する。

## 10局の比較対局

```sh
caffeinate -i python3 experiments/bogin-floating-rook/run_matches.py
```

定跡の生成・検証も自動で行う。結果は `results/floating-rook-10games.json`。
同じコマンドの再実行で再開し、完了済みの局は再実行しない。
途中局は保存した手順から新しいエンジンで続行し、探索表がリセットされた
再開回数を記録する。エラー局は自動再試行せず停止する。
別の新規バッチには `--output results/別の名前.json` を指定する。

5つの既知開始局面（16・18・18・22・24手目）を各定跡で1局ずつ。
すべて先手ShinON/support10/D10対、後手通常Rakuyou（定跡OFF）。
深さ15上限・秒読み10秒・Threads1・Hash512MB・追加256手上限。
後半の開始局面には今回の構想が既に一部入っており、独立した標本ではない。
序盤全体の優劣ではなく、定跡入口と各分岐以降の形を確認する。

対局ごとに新しいエンジンを使い、両定跡のコピーと入力ファイルのハッシュを保存。
実行中はコード・エンジン・評価データを変更しない。
終局は投了・入玉宣言、上限到達は未決着として集計から除外する。
千日手の独自裁定は行わない。過去バッチと合算せず、自動採用もしない。
定跡命中手数と20手ごとの進捗を表示し、棋譜・評価値を毎手保存する。

`--smoke` は別ファイルに保存する深さ1・追加2手の動作確認専用。

## 10局の確認結果

現行版3勝2敗、試験版4勝0敗1上限到達。入力・定跡のハッシュは一致し、
再開・エラーなし。全棋譜の指し手をネイティブエンジンで合法性確認した。
試験版の▲3九玉の定跡命中はexchange22とking24の2局だけ。
king24は41手目に▲2八玉へ移り、41・45・49・53手目で盤面・持駒・手番が一致。
結果の分類は未決着のままにする。勝率だけでは3九玉構想の成功とは判断しない。

採用前の確認点として、exchange22の23手目で▲2三飛成が可能なのに
定跡が▲2六飛を選ぶ点が見つかった。候補を限定した再探索でも成る手を支持。
ユーザーの確認後、この局面のみ▲2三飛成へ変更した（再探索は深さ23で
▲2三飛成+547／▲2六飛+133）。△3二金済みの別局面では▲2六飛を維持。
10局の結果と保存済み定跡は変更前の記録として残す。再対局は新しい
`--output` を指定し、変更前の結果へ追記しない。
全5組の比較図・監査結果・再探索ログは
`results/bogin-floating-rook/` の `batch-review.html`、`batch-audit.json`、
`review-pair.json` に保存。
