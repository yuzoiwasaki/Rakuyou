# 手番学習候補の通常探索比較：12局面・24探索

2026年10月11日。[分離環境と固定条件の準備](2026-10-11-tempo-full-search-preparation.md)に
従い、選定済み20更新平均化候補と現行基準を通常releaseで比較した。
24探索すべてが深さ12で完了し、選択手は2局面、PVは12局面すべてで変わった。
評価差は−153〜＋365cp。これを棋力改善や悪化の証拠とはせず、現行評価を維持する。

## 条件と検証

- validation6／test6、各side/result層から既に診断済みの1局面ずつ。
- depth12、MultiPV1、Threads1、Hash64MB、ShinYonenagaGyoku ON、OwnBook OFF、Ponder OFF。
- 各局面・各パラメータで新規プロセス。局面ごとに基準／候補の実行順を交互に入れ替えた。
- 各探索30秒、計24回上限。追加探索・深掘り・リトライなし。
- 固定の準備manifest SHAと設定、14コピーのSHA、対象12局面のSHA、運用6ファイルを
  実行前後で検証。候補以外のparamsを選択するオプションは設けていない。
- 準備ディレクトリに排他的な実行マーカーを残し、別の出力名による誤った再実行も拒否する。
- Native probeの再生でルートSFEN一致と全PVの合法性を検査。
  完了depth12、bestmoveとPV先頭の一致、停止なし、upper/lower boundなしを検査。
- 更新0、対局0、配備false、候補再選択false。実行中は各探索結果を逐次保存した。

```sh
python3 tools/learning/tempo/run_tempo_search.py \
  results/learning-pilot/2026-10-11-full-search-preparation-v1/manifest.json \
  --output results/learning-pilot/2026-10-11-full-search-comparison-v1
```

この実行は終了済みで、上記コマンドによる再実行はマーカーによって拒否される。

## 大きな差の扱い

[再静止探索](2026-10-11-selected-tempo-qsearch-review.md)では±1cp以内だったが、
通常探索の値は固定末端評価ではない。今回の探索はルート前の履歴を再生し、
主探索の反復深化・枝刈り・手順序・置換表を使用する。
`src/search.cc` の通常モードではHash Cutとhash scoreによる評価代用が有効で、
learning_modeの静止探索と条件が異なる。
`src/zobrist.cc` は起動時にrandom_deviceでキーを生成しており、各起動のキーを統一していない。

コピーされた候補paramsは基準と手番12バイト以外の全領域SHAが同じであることも
独立に再検証した。しかし同一基準による複数回の対照探索は今回の範囲に含めていない。
そのため微小な評価差による探索経路の変化と、同一評価で起こりうる探索の変動を
分離できない。Zobrist初期化が今回の差の原因だったとも断定しない。

たとえば最大差＋365cpのvalidation先手局面はbestmoveがS*3aのままで、
4手先以降のPVが大きく分岐した。これは初手の改善が証明された結果ではない。
選択手が変わった2局面についても、候補手が強くなった／弱くなったとは判定しない。
静止探索の「PV不変」を通常探索に一般化できないことが確認できた。

## 保存と判断

新規3テストで完了結果と差の集計、mateをcpとして減算しないこと、
停止／未完了深さ／bound／bestmove不一致の拒否を確認した。
実データでは24探索の完了・合法PV、元runtime6件とコピー14件の不変を検証した。
定跡・25cp補正・現行params・通常バイナリ・GUI設定を変更していない。
