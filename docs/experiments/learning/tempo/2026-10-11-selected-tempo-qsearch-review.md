# 選定済み手番候補の再静止探索：validation32・test32

2026年10月11日、ソース基準 `8d9a0e5`。
[初回学習](2026-10-11-first-tempo-learning-pilot.md)で選ばれた20更新の平均化候補を
固定し、基準との再静止探索比較を行った。64局面すべてでPVと末端は変わらず、
評価の変化は±1cp以内だった。追加学習や候補の再選択、現行評価への採用はしていない。

## 方法

- validation32局面、未使用test32局面を、既存のside/result層別の決定的な順番で選択。
  各splitの先手勝ち由来は先手側6件・後手側5件、上限draw由来は6件・5件、
  後手勝ち由来は5件・5件。split間のrunは独立。
- 初回reportの `selected_update=20` と候補SHAを検証し、その候補だけを比較。
  testを使った選択や設定変更は行わない。
- ルートごとに基準／候補のON・depth0静止探索を実施。計128回。
  各探索はfresh1MB TT、learning_mode=true。進行度とKP第4成分の一致を検証。
- Huffman境界でルートを復元し、ルートより前のNode履歴は引き継がない。
  PV末端の整数評価との一致、手番符号、特殊終了の適格性を検査する。
- 教師は過去のdepth15 cp。損失はL2を含まないsigmoid二乗誤差（gain1/600）。
  過去の勝敗別集計は観察用であり、勝敗を教師にする学習ではない。

```sh
python3 tools/learning/tempo/check_selected_qsearch.py \
  results/learning-pilot/2026-10-11-preparation-v2/manifest.json \
  results/learning-pilot/2026-10-11-pilot-run-v1/report.json \
  --output results/learning-pilot/2026-10-11-pilot-run-v1/selected-qsearch-check-v1.json
```

ツールは既存の出力を拒否する。候補指定や更新機能はなく、保存済みreportから選定候補を解決する。

## 結果

| 観察 | validation32 | test32 |
| --- | ---: | ---: |
| 適格な比較 | 32 | 32 |
| PV／末端の変更 | 0／0 | 0／0 |
| 評価値の変更 | 13 | 16 |
| ルートcp変化の範囲 | −1〜＋1 | −1〜＋1 |
| 基準損失 | 0.014582551870 | 0.014370005259 |
| 候補損失 | 0.014552145309 | 0.014351966698 |
| 相対損失低下 | 約0.2085% | 約0.1255% |
| cp RMSE（基準→候補） | 308.7190→308.3964 | 309.7772→309.5873 |
| 局面別の損失：改善／悪化／同値 | 9／4／19 | 9／7／16 |
| 探索nodes合計（基準→候補） | 124→126 | 178→178 |

validationは初回の64件と件数・探索条件が異なるため、初回の損失値と直接比較しない。
全体の平均損失は小さく低下したが、個別には悪化もある。validationの後手／後手勝ち5件、
testの後手／先手勝ち5件では層平均も悪化した。各層5〜6件のため、傾向の一般化はできない。
後手／上限draw5件では、validation4件・test2件の評価が変化し、層平均は小さく低下した。
引き分け確保能力や棋力の改善を示す結果ではない。

PVが変わらない場合でも、探索nodesはvalidationで2増えた。
今回の微小な差分では、この標本で固定末端の仮定を崩すPV切替は観測されなかった、
という限定した結論に留める。フル探索、局面の選択手、対局結果は未検証。

## 検証と保存

PV切替・悪化の記録、異なるルートの拒否、特殊終了の損失除外を確認する新規4テストが通過。
実データでは全64比較でルート一致・末端評価・適格性の検査が通過した。
通常バイナリ、4つのbinデータ、共通定跡の6ファイルは比較前後でSHA不変。
候補は別名ファイルのまま、定跡・25cp補正・運用設定を維持する。

## 判断と次の段階

この再静止探索確認を128回で閉じる。test32件は今回の選定候補の最終診断に使用済みで、
未使用扱いには戻さない。残り224件の教師品質は未測定。
歴史的教師パラメータの由来、長い共通手順による相関、上限drawの正式裁定がない点、
ローカルバックアップのみである点は引き続き制約になる。

次は基準と候補を別の作業ディレクトリで読み込む、同じ通常バイナリによる
小規模なフル探索比較の準備が候補になる。まず読み込み先・SHA・設定・時間／局面数の
上限を固定し、既に確認した少数局面で選択手とPVの変化を観察する。
共通定跡を変更せず、比較探索ではbookをOFFにして評価差を確認する。
この段階では対局数の拡大や評価項目の追加、testを見た係数調整へは進まない。
現行評価は据え置き、学習済み候補の採用判断は将来の別段階とする。
