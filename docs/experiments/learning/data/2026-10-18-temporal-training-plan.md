# 対局均等重みの学習：750局面・探索教師のみ

[追加教師の結果](2026-10-18-temporal-teachers-result.md)を受け、対局ごとの重みを
揃えた学習を準備した。候補への継ぎ足しではなく、隔離した現行版から差分ゼロで開始する。

## 実行

準備済み。リポジトリのルートで実行する。

```sh
python3 -m tools.learning.constraints.temporal_runner run
```

出力は `results/learning-pilot/2026-10-18-temporal-training-v1/`。
prepare・教師探索・ビルドは不要。今回のコマンドは新しい探索や対局を実行しない。
保存した特徴量で学習した後、native評価器で差分の反映を確認する。

`search/checkpoint.json` に１更新ごとに保存し、中断後は同じコマンドで最後の完了更新から
再開する。終了後は `summary.txt` と `comparison.json` に比較を保存する。
学習の進捗は25・50・100・200更新時に表示する。局面数・特徴数・上限補正の計算が
増えるため、以前より時間がかかる可能性がある。

## 固定した学習条件

- 学習750局面・255対局。検証187局面・63対局は更新に使わない。
- １対局からm局面なら各局面を1/mにし、255対局で平均する。
- 探索教師のみ。勝敗は診断指標として報告し、目的関数には混ぜない。
- 進行度や勝敗による追加の重み付けはしない。
- 従来と同じprojected方式、最大200更新、係数上限0.5cp、１更新の基準幅0.02cp、
  学習局面の変化上限100cp、L2 1e-6。
- 検証結果によるcheckpoint選択はしない。改善する更新が見つからず停止した場合も、
  その最終状態を報告する。

重みは損失だけでなく勾配にも適用する。１対局１局面なら従来の一様平均と一致する。
制約は重みとは別であり、重みの小さな局面を含む全750局面へ100cp上限を適用する。
学習キーはtrainの特徴だけから作る。追加データに伴いキー数と制約局面数も増えるため、
今回の比較は「時間を離したデータと対局均等重みを導入した一式」の効果になる。
局面追加・キー増加・重み変更の個別の因果効果まで分離した試験ではない。

## 比較と読み方

保存済みの旧projected-search候補（元255局面・固定200更新）と今回の候補を、
同じ750/187局面で評価する。旧候補の再学習はしない。
比較のための検証・native評価は、今回の学習が終了した後に行う。

表はtrain/validationそれぞれについて、元root・追加root・全体を分ける。
各群の中でも対局の重みを揃える。先後別・勝敗別の指標、整数評価と滑らかな評価の違い、
最大変化cpもJSONに保存する。旧データの引分け等の非教師局面151件は変化量の診断だけに使う。

損失の改善率は勝率ではない。特に、追加の後半局面だけ良くなり元rootが悪化する場合は
「全体の平均が良い」だけで採用しない。元の小さな検証集合は既に見た診断集合のままであり、
独立した棋力向上や厚みの獲得を証明するものではない。

## 実装と確認

新実装は以下。凍結済みの学習器・結果は変更していない。

- `weighted_objective.py`：対局均等の損失と勾配。
- `weighted_projected.py`：重み付き目的関数で更新を判定し、従来の局面上限補正を再利用。
- `temporal_runner.py`：入力固定、再開、最終比較とnative反映確認。

関連45テスト通過。１root/局で旧計算と一致、同じ対局の複製で重みが増えないこと、
有限差分による勾配、全rootの制約、保存再開を確認した。
実データ1088局面（旧469＋追加採用619）のゼロ差分native評価・特徴・保護成分を確認。
この準備では実データの学習更新・探索・対局・採用は行っていない。
