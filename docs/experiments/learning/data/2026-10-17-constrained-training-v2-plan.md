# 制約付き更新v2：係数を個別に抑え、局面上限超過だけ補正する

[v1の結果](2026-10-17-constrained-training-result.md)を受け、係数上限で全体の歩幅を
縮める処理を取り除いた。v1コード・plan・結果は変更せず、新モジュールと出力先を使う。

## 実行

準備済み。リポジトリのルートで次を実行する。

```sh
python3 -m tools.learning.constraints.runner_v2 run
```

出力先：`results/learning-pilot/2026-10-17-constrained-training-v2/`。
prepare・教師生成・ビルドは不要。学習とnative静的評価のみで、探索・対局はしない。
各完了更新を保存し、中断後は同じコマンドで再開できる。
結果は `summary.txt`、`comparison.json`、各方式のcheckpoint/reportに保存する。

## 比較条件

[v1計画](2026-10-17-constrained-training-plan.md)と同じ255学習・63検証局面、保存教師、
係数集合、ゼロ差分の初期値、各200更新、基準歩幅0.02、学習局面100cp上限、
係数0.5cp上限、L2、最大20回のバックトラックを使う。
旧方式legacy／修正版projected × 探索・勝敗・混合＝６試行。
旧方式は元runの全係数・全更新履歴・停止理由を再現することを確認する。
検証・native評価は全６学習完了後に行い、更新や停止の選択には用いない。

## 修正内容

通常の更新は旧方式と同じ。勾配から提案し、各係数を個別に±0.5cpで切り詰める。
全学習局面が100cp以内なら、学習目的関数が厳密に減る場合にそのまま採用する。
１係数の上限接近を理由に、他の係数の歩幅まで縮めない。

局面上限を超える提案にだけ、次の補正を追加する。

1. 超過局面の特徴に沿って提案を戻し、上限より1e-8cp内側を目標にする。
2. 全係数を係数上限と「現在値±今回の歩幅」の両範囲へ戻す。
3. 全局面が100cp以内か確認し、必要なら繰り返す。最大1000巡。
4. 実際の目的関数が厳密に減った場合だけ採用。不成立なら歩幅を半減してやり直す。

補正は逐次処理による実現可能な点の探索で、厳密な最短距離射影ではない。
全局面・係数上限を厳密に守ることを最終確認する。1e-8cpは内側への余裕であり、
上限超過の許容値ではない。補正のために１回の係数変更幅を増やすこともない。
非有限値や不正な初期状態は拒否する。

補正で全制約を満たせずバックトラックも尽きた場合は `direction_iteration_limit`、
実現可能な提案があっても誤差が減らなかった場合は `no_acceptable_improvement`。
いずれも数学的な収束証明ではない。補正の使用有無・試行回数・合計巡回数も記録する。
通常更新の旧方式との一致を保つため、v1のArmijo条件は使わず旧方式の厳密減少条件に戻す。

## 実データでの事前確認

３教師それぞれの保存0・25・50更新checkpointから、次の仮更新を計算した。
９件とも局面補正は不要で、修正版と旧方式の係数・損失・歩幅など旧方式の全返却値が
完全一致した。これは９地点での確認で、全更新履歴の事前再計算ではない。

旧方式の停止地点では、３件とも局面補正を使って制約内で改善できた。

| 教師 | 仮１ステップの目的関数減少 | 最大学習変化cp | 補正巡回数 |
| --- | ---: | ---: | ---: |
| 探索 | 0.0000499758 | 99.9999999900 | 3 |
| 勝敗 | 0.0001920813 | 99.9999999924 | 4 |
| 混合 | 0.0000972952 | 99.9999999904 | 4 |

これらは算術診断で、仮係数は保存せず連続更新もしていない。200回継続した場合の
効率・汎化は未確認。今回のユーザー実行で調べる。

全体355テスト通過後、再開テストを追加し、新領域６テストが通過した。
係数上限付近で他係数が通常幅で進むこと、局面境界での改善、正負の制約の干渉、
反復中の全上限保持、改善方向がない場合、不正入力、中断再開と完了後の抑止を確認。
実装は `tools/learning/constraints/projected.py` と `runner_v2.py`。
入力・コード・runtimeの結び付けはplanに記録し、実行開始時・終了時に確認する。

## 結果の読み方

まず100cp境界への補正が実際に使われ、その後も誤差が減るかを確認する。
更新回数が増えただけでは成功としない。勝ち／負け群、先後、両教師への誤差、
最大変化量を旧方式と比べる。検証集合は既に使用した診断集合であり、棋力の証拠ではない。
厚みの教師を新たに加えた実験でもない。候補選択・export・現行への採用は自動で行わない。
