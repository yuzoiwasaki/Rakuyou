# 探索教師v2：保存48探索を再利用した24局面の３者比較

[制約付き学習v2](2026-10-17-constrained-training-v2-result.md)の最終200更新
`projected-search` を固定し、現行版・旧探索教師候補との指し手の違いを確認する。
採用のための棋力試験ではなく、既に見た局面での挙動診断である。

## 実行

書出しと準備は完了。リポジトリのルートで次だけを実行する。

```sh
python3 -m tools.learning.constraints.behavior run
```

出力先：`results/learning-pilot/2026-10-17-projected-behavior-v1/`。
`summary.txt` は成功数・比較可能な３者組数・現行版／旧候補から指し手が変わった数を表示。
`report.json` は３者の結果と読み筋、`searches/` は新規通信ログと失敗記録を保存する。
export・prepare・ビルド・教師生成は不要。

## 条件

[以前の指し手比較](2026-10-16-hybrid-behavior-plan.md)で固定した24局面をそのまま使う。
先後×勝ち負けの４区分各６局面で、検証集合から選ばれた既使用の診断局面。
全履歴、depth15、Threads1、Hash64、MultiPV1、新米長玉ON、定跡OFF、各局面新規プロセス。
タイムアウトも旧比較と同じ30秒。新規は修正版の24探索だけ。
探索待ちの上限は計12分で、別に入力検証・起動等がある。実際の所要時間は未計測。

現行版・旧候補の計48探索は元の保存結果を再利用する。
旧plan・runtime・教師／候補との結び付け、attempt、検索結果の封印を確認。
全48件の保存PVを再生して診断が一致し、go depth15が１回でstopがないことを確認済み。
再利用結果のファイルSHAを新planへ固定した。元ファイルは変更しない。

新規も旧比較と同じ `behavior.diagnose` で分類する。
全３者が通常のcp結果である組だけを「指し手が変わった数」に入れる。
反復・mate・特殊終局・bound等は別扱い。最後の表示深さやPVが必要条件を満たさない
場合は比較から外れるため、成功件数だけで全24組を比較できるとは限らない。
探索値の増加は強さの増加とは扱わない。

失敗も保存して残りの局面へ進む。保存された成功・失敗は同じコマンドで再試行しない。
強制終了等でattemptだけが残った場合は再開を止め、記録を確認する。自動補充はしない。
