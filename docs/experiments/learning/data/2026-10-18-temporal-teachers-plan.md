# 時間を離した局面追加：選択完了と625局面の教師作成

[攻防範囲の監査](2026-10-18-training-coverage.md)を受け、同じ対局の後の局面を
追加する準備を行った。今回は教師作成まで。学習や採用は自動で続けない。

## 実行

準備済み。リポジトリのルートで実行する。

```sh
python3 -m tools.learning.constraints.temporal_teachers teachers
```

出力：`results/learning-pilot/2026-10-18-temporal-teachers-v2/`。
進捗は10局面ごとに表示し、`teachers.json` と `teachers/` に保存する。
prepare・ビルド・exportは不要。完了済み探索は再実行しない。
失敗・中断の記録も残し、自動再試行や別局面への差替えはしない。
終了後にaccepted/excluded/failedの内訳を確認してから学習段階へ進む。

最大625回のdepth15探索。後半の局面を含むので以前の教師作成より重くなる可能性がある。
各探索は新規プロセス、Threads1・Hash64・新米長玉ON・定跡OFF・MultiPV1。
基準版は既存hybridの隔離runtimeを読み取り利用する。
探索条件は同じdepth15で、watchdogだけ30秒から300秒へ延長した。
625件すべてがwatchdogまでかかった場合の待ち時間上限は約52時間であり、
これは所要時間の予想ではない。timeout後の結果は教師に採用しない。

## 固定した選択規則

元の採用済み学習255局・検証63局それぞれについて、元rootから24手後・48手後の
手番を追加候補とする。偶数手だけ進めるので、新米長玉を担当した同じ側の手番になる。
元rootを残し、最大３局面/局。元の実行単位のtrain/validation分割を保持する。
検証側も同じ規則で広げるが、既に何度も見ている検証集合であり、未知の評価集合ではない。

元棋譜の長さ不足、違法・終局・反復、既存469rootまたは今回候補同士の局面重複は除外。
重複は手数を除く盤面・持駒・手番、および180度回転＋先後交換も確認する。
候補同士が衝突した場合は両方除外し、trainを先に選んでvalidationを押し出さない。
今回、重複・違法・反復の除外はなく、長さ不足11件だけだった。
全過去履歴との非重複を保証するものではない。

選択は評価値、勝敗、交換の有無、進行度によって変更しない。
後の手数だから必ず終盤とは呼ばない。元の「早・中・終盤から１つずつ」という案は
段階境界の調整を避け、再現しやすい時間間隔の固定に具体化した。
今回は元rootの古いcp上限1000を追加局面の選択には適用していない。
そのため大差の局面が多くなる可能性があり、教師完成後に分布を必ず確認する。

| --- | ---: | ---: | ---: | ---: |
| 学習 | 255 | 501 | 756 | 319 |
| 検証 | 63 | 124 | 187 | 77 |

学習側は247局が２件追加、７局が１件追加、１局が追加なし。

進行度の範囲はそれぞれ約0.37〜0.96、0.36〜0.92で、選択後の記述にのみ使う。
新しい対局、最近の評価対局、保留test対局は取り込んでいない。

## 教師と学習を分ける理由

既存318件の教師は保存済みのまま再利用し、新しい625件だけ探索する。
学習用特徴量と基準静的評価は同じ隔離基準版から抽出済み。
詰み値、宣言・投了、反復PV等は従来の分類規則で除外し、正常なdepth15のcp教師だけを使う。
不完全な探索は失敗として保持する。候補の評価データは使わない。

元の１局面だけの結果と追加後を比較できるよう、今後の学習では現行版からのゼロ差分開始、
同じprojected更新器と探索教師を維持する案。混合率変更は同時に行わない。

重みは教師除外後に決める。ある対局で採用された局面がm件なら各局面の重みを1/mとし、
各対局の総重みを揃える。分割内でG局なら目的関数の各局面の係数は1/(Gm)。
勝敗・進行度で追加の重みを付けない。評価集計も元rootと追加rootを分け、
後半局面が増えただけの数値変化を改善と呼ばない。

実際の採用数・cp分布を確認する前に学習runnerは実行しない。
全体の受入数だけでなく、対局ごとの追加件数、先後・勝敗・進行度別の偏りを確認する。
この段階では「交換後を直接学べる局面が増える」という準備上の前進であり、
棋力や厚みが改善したという成果ではない。
