# 勝局群・敗局群を確認する混合学習：固定１条件の比較

[共通改善方向の診断](2026-10-20-common-direction.md)では、同じ上限内で両群を改善する
一歩が見つかった。今回は、その確認を毎回の更新に加える方式を、保存済みの通常混合と比較する。
目的は「勝局への適合が敗局での悪化を埋め合わせる」進み方を抑えられるかの確認。
厚みの指し方を直接教える実験ではない。

## 固定条件

- 同じ学習750局面・検証187局面、対局均等重み、探索／勝敗50/50。
- 差分ゼロから最大200更新。係数上限0.5cp、学習局面変化上限100cp、
  最大ステップ0.02cp、L2は1e-6。従来と同じ局面補正を使用する。
- 通常方向を先に試す。全体の混合＋L2、勝局群と敗局群それぞれの混合損失、
  両群それぞれの勝敗損失、計５項目がすべて1e-12を超えて低下したら受理。
- 通常方向で受理できない場合、各群の混合勾配を長さ１にして足した方向を試す。
  各方向で0.02から半減20回まで。前回の小診断は半減６回だったが、
  今回は保存済み通常学習の半減予算20回に揃える。
- 両方向とも不成立なら、その時点で停止。条件緩和・混合率変更・予算延長はしない。

群を均す方向にL2の勾配は含めないが、受理時の全体損失にはL2を含める。
上限補正後の係数で５損失を実計算する。群内の損失は群内で対局均等重みを再計算する。
条件を満たすのは滑らかな学習スコア上の群平均であり、個別局面や整数評価の単調改善は保証しない。
通常方向からの切替と厳しい受入条件を一体として比較するため、両者の効果は分離できない。
更新数は同じ上限だが、試行回数と実行時間を同じにした比較でもない。

## 実行

実装は `group_guarded.py` と `temporal_guarded.py`。旧実験のコード・保存物を変更しない。
準備済みの新出力先は `results/learning-pilot/2026-10-20-temporal-guarded-v1/`。
`plan.json` のSHA256は
`537fcd88b4ed270cc113d44498151989d307db3fd7b3f0d360366b19092c69bb`。
準備後の読み戻しでも、入力750／187局面・保存対照・コードの一致を確認した。

リポジトリのルートで実行する。

```sh
python3 -m tools.learning.constraints.temporal_guarded run
```

教師作成・ビルド・prepareの再実行は不要。完了した更新ごとにcheckpointを保存する。
中断時は同じコマンドで再開できる。学習終了後の集計で中断した場合も、学習を繰り返さず集計する。
入力・コード・通常混合の保存結果との結び付けが変わった場合は停止する。

## 読む結果と判断

`summary.txt` は通常混合と新方式の学習／検証・勝局／敗局・元／追加局面の結果を表示する。
`comparison.json` は探索専用の保存対照も含み、整数／滑らかなスコア、先後別、引分診断を残す。
`mixed/checkpoint.json` の各更新には採用方向、群別損失の前後、棄却理由、補正・半減回数が入る。
停止時は両方向の試行履歴を `stop_diagnostic` に残す。

まず、受理できた更新数と方向切替の頻度を確認する。すぐ停止した場合は、この限定方式では
十分に進めなかったと判断する。特徴不足や共通改善方向が存在しないことの証明にはしない。

学習群の改善は受入条件そのものなので、それだけを成果とは数えない。
最終状態の検証局面、とくに敗局群と先後別への転移を確認し、通常混合と比較する。
検証局面は既に何度も見ており、独立した証明にはならない。
検証成績で途中checkpoint・方向・混合率を選ばない。
群平均の改善を厚みの獲得や勝率向上と読み替えず、対局・採用は結果を読んで別途判断する。

準備段階では実データの学習を開始していない。関連57テストが通過し、
新規５テストで通常方向の優先、敗局悪化時の切替、完全衝突時の停止、上限補正、
完了状態の再実行、群別履歴の不整合と計画変更の拒否を確認した。
