# 探索教師候補：同じ局面での指し手比較

2026年10月16日。[三方式の初回結果](2026-10-16-hybrid-learning-result.md)を受け、
ユーザーが継続を指示。探索のみで学習した最終候補を対象とする。

## 目的と今回の範囲

静的評価の変化が、実際に選ぶ手と読み筋に届くかを見る。
金銀を支え合う形に組む、前に出る、受けや駒取りを優先して前進を見送る、
といった指し方の変化を具体的な局面で確認するための材料を保存する。
特殊な△６三金などを正解にする採点は行わない。

まず24局面の同条件探索を行う。対局は次の段階とする。
既存の `paired_selfplay.py` は同じ実行ファイルの新米長玉ON対OFFを目的とし、
千日手・連続王手などの判定にも不足がある。そのまま候補対現行版の棋力検証に使わない。
新たな対局では、別の開始局面を先に固定し、同じ開始局面で候補と現行版の先後を
入れ替える。今回の局面比較をその対局の代わりにはしない。

## 局面と条件

- 学習時に採用した検証63局面から、先手／後手×棋譜の勝ち／負けの4層を各6局面。
- 局面IDの固定ハッシュ順で24局面を選ぶ。評価差や指し手の変化を見て選び直さない。
- 元の棋譜履歴をそのまま使う。勝敗ラベルは層別表示のためで、手の正解ではない。
- この検証集合は候補比較に使用済み。未知データでの棋力検証とは呼ばない。
- baselineは学習時の隔離runtime、candidateはsearchの最終候補の隔離runtime。
- 両側とも新米長玉ON、定跡OFF、Threads1、Hash64MB、MultiPV1、depth15。
- 1探索の待ち時間30秒、局面・版ごとに新しいプロセス。合計48探索。
- 評価値の詰み表記、反復、特殊終端は診断として残す。通常の比較から外れた件数も示す。
- timeout・不正な読み筋・通常探索の深さ不足などは失敗として記録し、黙って補充しない。

最大の探索待ち時間は48×30秒＝24分。起動・合法性確認などは別で、所要時間の予測ではない。
同じ深さでも読む局面数・時間は変わりうるので、保存した探索情報も確認する。

## 読み方

最初は、最善手が変わった数と、その先後・元棋譜勝敗別の内訳を見る。
変わらなかったことは学習の失敗を意味しない。元から十分よい手だった場合や、
順位を逆転するほどの差でなかった場合もある。

変わった局面は両版の読み筋を並べ、次を調べる。

1. 金銀の支えや玉の逃げ道がどう変わるか。
2. 駒取り、王手、相手の攻めへの対応を遅らせていないか。
3. 先の展開で厚みが攻め・受けに役立つか。短い読み筋で決められない場合は未判定とする。

候補の探索点が上がっただけで「その手がよい」とは判定しない。
評価関数自体が変わっており、両版の点数の差は共通の物差しによる改善量ではない。
指し手が変わった割合も、棋力や厚みの達成率ではない。
次の対局・必要な追加確認を決める材料にする。

## 実行と保存

候補のexportは完了。元の `bin/` は変更せず、469局面で保存済みの候補評価と
export後の評価が一致することを確認した。ゼロexportの一致と変更領域の監査も通過。
候補は `results/learning-pilot/2026-10-15-hybrid-v1/search/runtime/bin/release`。
exportの再実行は既存出力を拒否するため、実行し直さない。

準備と探索のコマンド（リポジトリのルート）：

```sh
python3 -m tools.learning.playtest.behavior prepare
python3 -m tools.learning.playtest.behavior run
```

準備済みなら `run` のみ実行する。準備済みかどうかは下記の完了記録またはMEMORYで確認。
既定保存先：`results/learning-pilot/2026-10-16-hybrid-behavior-v1/`。
`summary.txt` に集計、`report.json` に局面と両版の結果、個別ファイルに探索ログを保存する。

完了した探索は同じ `run` コマンドで再実行せずに読み込む。
失敗・結果のないattemptは勝手に再探索しない。その場合は記録を残してエラーを共有する。
準備で入力・runtime・コードを固定するため、途中で変更があれば続行を拒否する。
今回の実装は新しい `tools/learning/playtest/` に置き、終了した学習のコードを変更しない。

この段階では学習の再実行、更新器の変更、対局、現行評価への採用は行わない。
