# 両群確認型候補の指し手比較：24局面・48探索

[学習結果](2026-10-20-temporal-guarded-result.md)で固定した200更新後の候補を、
現行評価と同じ局面から探索させる。追加学習・混合率変更は行わない。
敗局群の静的な見積りの改善が、指し手や読み筋の変化に届いているかを確認する段階。

## 局面と条件

既存の検証187局面を、元／追加 × 先手／後手 × 勝局／敗局の８区分に分け、
各３局面、計24局面を選ぶ。固定文字列 `guarded-behavior-v1:` と局面IDのSHA256順で選び、
各区分内では１対局１局面までとする。評価値・候補との差・指し手は選択に使わない。
区分をまたぐ同じ対局の使用は許すため、24の独立対局とは言えない。
局面の重複や反復を検出した場合は停止し、都合のよい代替局面を補充しない。

各局面で現行版と候補を新しいプロセスで探索させる。計48探索。
深さ15、１スレッド、Hash64MB、MultiPV1、新米長玉ON、定跡OFF、ponder OFF。
タイムアウトは双方120秒。30秒の過去試走より待機時間を延ばすが、
深さを満たさない結果は通常の比較に含めない。等時間の棋力比較ではない。
両者の評価値の差は、評価の物差し自体も違うため棋力向上量とは扱わない。

## 実行

実験専用runtimeへの候補書出しと準備を済ませてから、次だけを実行する。

```sh
python3 -m tools.learning.constraints.guarded_behavior run
```

出力先：`results/learning-pilot/2026-10-20-guarded-behavior-v1/`。
候補runtime：`results/learning-pilot/2026-10-20-temporal-guarded-v1/guarded-mixed/runtime/`。
現行の `bin/` は変更しない。export・prepareの再実行は不要。

成功済みの探索は保存され、再実行時に再利用する。探索途中の中断・失敗は記録を残して停止し、
自動再試行や結果の上書きはしない。その場合はログを確認してから対応する。
詰み・反復・評価値の上下限などは別の診断扱いで残し、通常比較から区別する。

`summary.txt` に成功数、通常比較できた組数、最善手の変化数が出る。
`report.json` に全24局面の両者の指し手・読み筋・診断と８区分別集計、
`searches/` にコマンドとエンジン応答を保存する。

## 結果の読み方

指し手の変化数だけで良否は決めない。変化があれば、攻めを継ぐか守るか、
金銀の支えを残すか、交換後に守備が足りるかを読み筋と盤面で確認する。
改善例だけでなく、勝局側の改善減少に対応する悪化も見る。
少数の変化局面を次の正解ラベルにはせず、深さ追加を繰り返して望む手を追わない。

指し手が変わらない場合も、深さ15・選択した24局面での結果に限定する。
厚みの個性や負けにくさを得た証明にはならない。
検証局面はすでに集計に使用しており、独立したテストでもない。
対局を追加するかはこの結果の確認後に判断する。

## 準備の検証

候補の書出しでは、差分ゼロの書出しが現行paramsと同一、変更領域が許容範囲内、
全1088局面の整数評価が保存結果と一致することを確認。
入力・学習checkpoint・候補差分・runtime・コードをハッシュで固定する。
選択した24局面はnative probeで棋譜履歴とSFEN・局面識別子を照合する。

新規５テストで区分の均等性、評価値を使わない選択、区分内の対局重複回避、
局面重複と計画変更の拒否、成功結果の再利用、失敗の保存と再試行禁止を確認。
関連constraints62テストと既存behavior７テストが通過。実探索は手元での上記コマンド実行時に行う。

準備と読み戻しが完了。選択24局面は23対局由来で、両runtimeのUSI起動・ready応答も確認した。
探索コマンドは送っていない。追加局面の局面識別子は棋譜のnative再生から取得して計画へ固定した。
