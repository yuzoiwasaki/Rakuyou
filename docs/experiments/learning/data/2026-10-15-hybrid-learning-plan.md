# 探索評価・勝敗・混合を同じ局面で比較する実験

2026年10月15日。ユーザーは、特殊な△６三金を好みの正解として掘り下げる方針を終え、
探索評価だけ・勝敗だけ・混合の比較へ進むことに同意した。
この文書は新しい実験の設計と実行手順。長時間の教師生成と学習は手元で実行できる。
現行評価への自動採用はしない。旧実験のmarkerや結果は変更しない。

## 今回確かめること

「最終的に負けたが、この途中局面はまだ戦える」という探索の判断と、
「実際にはこの対局で負けた」という結果を、同時に教える価値を調べる。
特定の金寄りを正解にせず、同じ局面・同じ評価の変更範囲で三方式を比較する。
厚みの棋風を直接教える実験ではない。指し方の個性と実戦成績は、候補ができた後の別の評価になる。

## データと教師を揃える

- 既存の拡大勝敗準備の383学習元局面、80検証元局面、別枠の使用済み後手draw6件を再利用。
- 一次比較は決着した256学習／64検証局面。全方式で同じ採用局面・同じ重みを使う。
- 学習draw127、検証draw16、別枠draw6はどの方式の損失・勾配・学習キーにも入れない。
  形勢の変化だけを別集計する。探索だけの方式にもdrawを追加せず、比較条件を揃える。
- trainからのみKP／PPキーを決める。検証にしか出ないキーの差分は0。
- 元のrun分割、対局ごと1局面、先後・勝敗ラベルを維持する。testや新しい対局は使わない。
- 決着320局面に現行baselineのdepth15探索評価を生成する。手番側視点、ON、定跡OFF、
  Threads1、Hash64MB、MultiPV1、fresh process、各探索30秒。過去の対局中cpは教師にしない。
- 詰み・特殊終端・反復等で通常のcp教師にできない局面は、全方式から共通に除外。
  train／validationそれぞれ元の決着件数の90％以上と、先後×勝敗4層の存在が必要。
  満たさなければ学習に進まない。除外した局面の補充はしない。
- timeout、深さ不足、入力不整合、処理エラーは通常の除外にしない。失敗を残して学習を止める。

元局面の**静的評価**を三方式すべての予測に使う。
前の厚み実験の静止探索末端と、勝敗学習の元局面をそのまま混ぜることはしない。
今回は「元局面の配置だけでも、先を読んだ形勢と結果を予測できるか」という設計。
静的評価では途中の駒取りや具体的な攻めを表し切れない制約は残る。

検証runは既に使用済みで、この比較も開発用の診断である。
過去棋譜のruntime同一性は不明。現在の教師を付け直しても、過去の指し手・結果が
現在のエンジンから生成されたことにはならない。

入力：[拡大勝敗準備](2026-10-14-outcome-expanded-preparation.md)。
使用するreport・ラベル監査・元データ・runtime・コードをSHAで固定する。

## 三方式の損失

候補の元局面評価をs、現行探索の教師をq、勝ち1／負け0をyとする。

```text
p = sigmoid(s / 600)
教師の値 t = (1 - alpha) * sigmoid(q / 600) + alpha * y
損失 = mean(-t*log(p) - (1-t)*log(1-p)) + (L2/2)*sum(delta^2)
```

| 方式 | alpha | 教える内容 |
| --- | ---: | --- |
| search | 0 | 現行探索の形勢 |
| outcome | 1 | 実戦の勝敗 |
| mixed | 0.5 | 同じ尺度で両方を半分ずつ |

半々は事前に固定した比較点で、最適な比率という主張はない。
探索だけにも同じ交差エントロピーを使う。以前のsigmoid二乗誤差とは異なるため、
旧実験の改善率と直接比較しない。勝敗だけの損失は従来の二値損失と対応する。
sigmoidの値は層別抽出した集合上の学習尺度であり、実戦勝率の校正値ではない。

## 変化を観測するための更新条件

旧RMSpropの20更新・1係数0.01cp上限は変更せず、新しい実験専用の更新器を使う。

| 条件 | 値・規則 |
| --- | --- |
| 開始点 | 各方式とも現行評価＋ゼロ差分 |
| 対象 | 同じ学習キーのKP／PP。進行度・手番等の保護は継続 |
| 損失の集計 | 全学習局面の等重み平均＋差分L2=1e-6 |
| 更新予算 | 各方式最大200更新 |
| 更新方向 | 全勾配を最大絶対勾配で割り、最急降下方向へ移動 |
| 初回提案幅 | 1係数あたり最大0.02cp／更新 |
| 係数上限 | ±0.5cp（既存native差分形式の範囲内） |
| 学習局面の上限 | baselineからの滑らかな評価差が最大100cp以内 |
| 更新を受け入れる条件 | 学習損失＋L2が厳密に減少し、上限内。失敗なら幅を半減、最大20回 |
| 停止 | 200更新、勾配0、または改善する許容幅が得られない場合 |
| 保存 | 0／25／50／100／200更新と最終状態。途中の平均化はしない |
| 比較対象 | 学習条件だけで止まった最終状態。検証でcheckpointを選ばない |

更新幅や100cpは効果を保証する値ではなく、今回の比較用の上限。
上限到達、実際の変化量、学習損失の推移を残し、動かなかった理由を区別する。
検証・drawの最大変化も確認し、全469局面の滑らかな差が100cpを超える候補は
探索用exportを許可しない。この判定は候補の棄却フラグだけで、学習の幅や停止点へ戻さない。
整数値は丸めで滑らかな上限と僅かにずれるため、整数差も別途記録する。

学習側の誤差が下がることと、別棋譜で強くなることは違う。
256局面に多数の係数という制約も残る。今回はより観測しやすい更新で三方式を
比較する段階であり、これだけで採用や大規模化を決めない。

## 出力と判断

`comparison.json` に各方式の以下の値を保存する。

- 共通指標として、探索教師への誤差・勝敗への誤差を両方測る。方式ごとに異なる
  学習目的の損失値を、そのまま大小比較しない。
- 学習／検証、先手／後手、勝ち／負け、整数化前／native整数化後を分ける。
- 教師とのcp差、勝者方向へ動いた件数・逆方向の件数、局面評価の変化量。
- drawの評価変化。旧後手draw6件は新検証へ混ぜない。
- 共通除外、各方式の更新数・停止理由。細かな更新履歴は各checkpointに保存。

`summary.txt` はユーザーが短く結果を共有するための表。
正の改善率は誤差の減少であり、勝率の増加ではない。
全体の平均だけで採用せず、以前繰り返した負け側の悪化が残るか、
学習側だけへの適合で終わっていないか、整数化による見かけの改善でないかを見る。
最良方式や採用候補の自動選択は行わない。

## 手元での実行

リポジトリのルートで実行する。既存のprobeとexporterを再利用し、新しい依存ライブラリは不要。
通常の `--learn` や `make release` は実行しない。

```sh
python3 -m tools.learning.hybrid.data prepare
python3 -m tools.learning.hybrid.data teachers
python3 -m tools.learning.hybrid.runner
```

既定保存先：`results/learning-pilot/2026-10-15-hybrid-v1/`。
`prepare` は新規作成専用。同じ保存先を二度作らない。
準備済みなら `teachers` から進める。
別の保存先は各コマンドに同じ `--output results/...` を指定する。

教師生成は最大320探索。30秒×320＝160分は探索待ち時間の上限で、プロセス起動等は別。
通常の所要時間の予測ではない。10件ごとに短い進捗を表示する。
学習も25／50／100／200更新時に進捗を表示する。

教師生成は完了した局面を保存し、再実行時にその局面を飛ばす。
timeout等もログを保存して失敗として固定し、勝手に再探索しない。
強制終了で結果のないattemptや破損記録が残った場合は明示的に止める。
失敗を取り除いたりmarkerを削除して続けず、記録を見て次の扱いを判断する。
学習は最後に保存した算術checkpointから再開でき、同時実行をOS lockで防ぐ。
入力・教師・コードが途中で変われば再開を拒否する。

学習完了後に、指定した最終候補を独立runtimeへ出す任意のコマンド：

```sh
python3 -m tools.learning.hybrid.export --arm mixed
```

`--arm search`、`--arm outcome` も指定できる。最終候補の静的評価、exportの変更領域、
ゼロexportの一致を監査する。出力は各方式の `runtime/bin/release` と `params.bin`。
通常の `bin/` は変更せず、探索・対局・GUI切替も行わない。
この段階の対局計画や個性の行動比較は、三方式の結果を見て別途決める。
