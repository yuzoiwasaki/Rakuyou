# 探索教師v2：現行版との16局対局

[24局面の挙動確認](2026-10-17-projected-behavior-result.md)を受け、ユーザーが対局試行を承認。
固定したprojected-searchの200更新候補と現行版を、以前と同じ８開始局面・先後交代で対戦させる。
比較対象は現行版で、旧学習候補との直接対戦ではない。

## 実行

準備済み。リポジトリのルートで次を実行する。

```sh
python3 -m tools.learning.constraints.match run
```

出力先：`results/learning-pilot/2026-10-17-projected-match-v1/`。
終了後は `summary.txt` と `report.json`、各棋譜・毎手の探索ログは `games/` に保存される。
prepare・export・ビルドの再実行は不要。実際の対局はまだ行っていない。

## 前回と揃える条件

[旧候補のv4試走](2026-10-17-hybrid-match-plan.md)から開始局面と設定を読み取り、
新planへ固定した。候補runtimeだけを修正版へ替える。対局は全16局を新規に指し、
旧棋譜を新対局の結果として引き継がない。

| 項目 | 条件 |
| --- | --- |
| 開始局面 | 既存の手作り８局面、各12手の全履歴 |
| 組合せ | 各局面で候補の先後を交代、計16局 |
| 探索 | 両者depth15、Threads1、Hash64 |
| オプション | 両者新米長玉ON、定跡OFF、Ponder OFF |
| プロセス | 対局ごとに両エンジンを新規起動 |
| watchdog | １手300秒、前回v4と同じ。持ち時間制ではない |
| 手数上限 | 開始局面から追加256手。打切りは未決着 |
| 判定 | 同じnative referee。合法手、詰み、正式な４回反復、連続王手、宣言勝ちを扱う |

８局面は先手／後手新米長玉の構えそれぞれ、四間飛車・三間飛車・中飛車・居飛車の４種類。
以前の16局で見た局面なので、独立な未知序盤の検証とは呼ばない。

対局ループの実行・判定・記録は修正済みの旧match実装を再利用し、そのコードは変更しない。
正常bestmoveが返った場合、最後のinfoが要求深さ未満だったりPV先頭が異なったりする
ケースは明示して扱う。最後の表示cpが実際の最終手の評価とは限らない。
timeout・不正手・プロセス異常はエラーとして保存し、勝敗に算入しない。

## 中断・再開

同じコマンドは完了済みの対局を再実行せず、未着手の対局から進む。
途中で失敗した対局や結果のないattemptが残った場合は、自動で最初からやり直さず停止する。
その場合はメッセージを共有し、保存ログを確認する。対局中のハッシュ状態を
復元できないため、途中の指し手から継ぎ足して同じ試行とみなさない。

## 何を判断するか

まず完了数・エラー・引分け／未決着の理由を確認し、勝敗を先後・開始局面の対で見る。
旧候補の６勝８敗２分とは記述的に比べるが、少数の固定序盤・同じ深さの結果で
棋力向上やEloを確定しない。候補を変えると対戦相手の応手も変わる。
厚みについては金銀の支えが役立ったか、受けが必要な場面で攻めを続けたかなどを
棋譜で別に確認する。勝率だけで個性の獲得とは扱わない。

学習追加・候補変更・定跡変更・現行評価への採用は行わない。
