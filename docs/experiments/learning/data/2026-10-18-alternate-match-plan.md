# 探索教師v2：別の開始８局面による16局試走

[改善２局・悪化１局のレビュー](2026-10-18-projected-match-review.md)を受け、
候補と探索条件を固定し、開始局面だけを変える次の試走を準備した。
前回に近い序盤の変化に結果が耐えるかを見る。広い戦型での棋力を測る試験ではない。

## 実行

準備済み。リポジトリのルートで次を実行する。

```sh
python3 -m tools.learning.constraints.alternate_match run
```

出力先：`results/learning-pilot/2026-10-18-projected-alternate-match-v1/`。
`summary.txt`、`report.json`、`games/` に結果と毎手の記録を保存する。
prepare・export・ビルドは不要。完了局は同じコマンドで再実行せず、未着手局から再開する。
対局途中の中断・失敗は記録を残して止める。その場合はログを確認してから対応する。

## 結果を見る前に固定した開始手順

元の８区分（先手／後手新米長玉×相手の四間飛車・三間飛車・中飛車・居飛車）を維持し、
各12手の開始手順の１手を、区分内で一律に置き換えた。

| 新米長玉の側 | 変更 | 局面上の違い |
| --- | --- | --- |
| 先手 | 11手目▲５六歩を▲７六歩へ | ５筋の歩は５七に残り、角道が開く |
| 後手 | 12手目△５三銀を△９四歩へ | 銀は４二に残り、９筋の歩が進む |

定義ファイルは `docs/experiments/configs/projected-alternate-starts-v1.json`。
全８手順を評価・探索する前に固定した。探索値・勝敗で候補を選別していない。
特に後手の銀の配置が異なるため、前回と同じ銀の形が自然に作られるとは限らない。
この違いを含めて、同じ学習候補が少し異なる序盤に対応できるかを見る。

## 重複確認の範囲

次の保存集合に対して、開始局面の盤上・持駒・手番が一致しないことを確認した。
手数部分は比較から除き、180度回転＋先後交換した形も同一として検出する。

- 学習・検証・診断の469局面について、保存された初手から各rootまでの全履歴。
- 旧候補16局と修正版16局の計32局について、保存された全実戦局面。
- 今回の８開始局面同士。

全８件がこの範囲で非重複。手順前後で同じ局面になったものや、単なる先後反転はない。
過去に存在するすべての棋譜・実験成果物を網羅した監査ではなく、将棋全体で未知の局面
という意味ではない。今後の対局途中に旧局面へ合流する可能性もある。
今回の開始局面自体も、構造的には以前の序盤に近く、８件が独立無作為標本とは言えない。
検証に用いたデータ・32棋譜のSHAをplanに記録した。

## 対局条件と判断

候補は同じprojected-searchの固定200更新版、相手は同じ現行版。
両者新米長玉ON、定跡OFF、Threads1、Hash64、depth15、１手watchdog300秒。
各開始局面で候補の先後を交代し、全16局を新しく指す。各局で両プロセスを新規起動。
開始12手から追加256手で打切り、未決着として保持する。正式な反復はrefereeで判定。
エラー・timeoutを敗戦として数えない。旧対局ループ・判定コードは変更せず再利用する。

結果は今回の16局として集計し、前回の９勝５敗２未決着と並べる。
最初から両者を合算して大きな標本のように扱わず、先後・新米長玉側・８区分の違いを見る。
同じ深さは同じ持ち時間ではない。等時間の実用棋力試験は別段階である。
今回も好結果なら追加検証の理由になるが、即時採用や個性の獲得を意味しない。
結果が悪化しても、この16局だけで方式全体を否定せず、開始条件への依存を観察する。
