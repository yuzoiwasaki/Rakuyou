# 同じ750局面での50/50混合比較

[探索教師のみの結果](2026-10-18-temporal-training-result.md)を固定対照とし、
探索評価と最終勝敗を50/50で混ぜた学習を１回行う準備。
検証敗局群の悪化が減るか、その代償として探索教師との整合性が崩れるかを確認する。

## 実行

準備済み。リポジトリのルートで次を実行する。

```sh
python3 -m tools.learning.constraints.temporal_mixed run
```

出力：`results/learning-pilot/2026-10-18-temporal-mixed-v1/`。
prepare・教師探索・ビルドは不要。新しい探索・対局は行わない。
１更新ごとの保存があり、中断後は同じコマンドで再開できる。
完了後は `summary.txt`、`comparison.json` を確認する。

## 変えるもの・固定するもの

目的関数だけを、探索教師の損失50％＋勝敗教師の損失50％へ変更する。
探索評価は従来どおりsigmoid(cp/600)に変換し、勝敗は手番側の勝ち１・負け０。
同じ対局の局面数にかかわらず、対局の総重みを揃える。

学習750局面、検証187局面、trainのみの107964キー、隔離現行版からのゼロ差分開始、
projected方式、最大200更新、係数上限0.5cp・学習局面上限100cp・更新幅0.02cp・
L2 1e-6を固定する。データの追加・除外・進行度重み・混合率探索はしない。
検証結果で更新回数を選ばず、学習で決まった最終状態を評価する。

元255局面で学んだ旧候補と、今回と同じ750局面で学んだ探索教師のみの候補は、
保存済みの比較結果をそのまま再利用する。両者の再学習・再評価は不要。
新しいnative評価と保護成分の確認は、混合候補の学習終了後だけに行う。

## 結果の読み方

集計には元root・追加root・全体に加え、敗局群も表示する。
先後・勝局群・滑らかな評価・引分け診断はJSONに保存する。

優先して見るのは以下。

1. **検証敗局群**の勝敗損失が探索教師のみより改善するか。学習内だけの改善では足りない。
2. **元の検証root**の探索損失を悪化させていないか。
3. 勝局群・先後の片側に大きな悪化が隠れていないか。

この３点を合わせて判断し、混合目的関数の数値を探索専用の目的関数と直接比べない。
全て同じ定義の探索損失・勝敗損失で比較する。改善率は勝率ではない。
改善しても即採用せず、悪ければ混合率を細かく動かして勝てる数値を探し続けない。

混合は敗局中の良い局面にも負けラベルを与えるため、必ず良くなるものではない。
既存検証は既に見た診断集合で、独立した棋力検証にはならない。
