# 両群確認型候補：運用定跡７入口・14局の対局確認

[24局面の指し手比較](2026-10-24-guarded-behavior-result.md)で、候補の影響が指し手まで届くことを確認した。
次は同じ200更新後の候補を固定し、現行評価との対局を新たに14局行う。
追加学習や係数変更はしない。

## 固定条件

過去の運用定跡比較と同じ７入口を使用し、各入口で候補の先後を交替する。
７入口すべてを使い、指し手比較の良し悪しや過去の勝敗では選別しない。
定跡の手順を初期履歴として与えた後は、両者とも定跡OFFで指す。

- 深さ15、１スレッド、Hash64MB、新米長玉ON、ponder OFF。
- 各対局で両エンジンを新しく起動。１手の待機上限300秒。
- 開始局面から最大256手。上限に達しても終局していなければ未決着。
- 千日手・連続王手・合法手・入玉宣言は既存のnative判定器を使用。
- タイムアウトや不正な出力はエラーとして停止し、負けや引分へ置き換えない。

これまで検証した対局ループ・終局判定・記録形式を使用する。
探索の最終表示深さが15未満でも、`go depth 15`への`bestmove`が時間内に返った場合は
既存方針どおり診断フラグを付けて保存する。表示される最終PVと実際の最善手が異なる場合も記録する。

## 実行

準備済みのリポジトリのルートから、次を実行する。

```sh
python3 -m tools.learning.constraints.guarded_match run
```

新しい出力先は `results/learning-pilot/2026-10-24-guarded-book-match-v1/`。
以前の候補の対局結果は流用しない。現行版と今回の候補runtimeは、指し手比較で使用したものを固定する。
新たなexport・prepare・ビルドは不要。現行の `bin/` や定跡は変更しない。

完了済みの対局は再実行しない。対局途中の中断・失敗では部分棋譜とコマンド・応答を残す。
失敗した対局の自動再試行は行わないため、エラー時は保存記録を確認してから対応する。
部分棋譜からの自動続行は実装していない。
