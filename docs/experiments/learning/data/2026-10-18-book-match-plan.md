# 運用定跡の入口からの14局比較

[開始局面の照合](2026-10-18-start-book-audit.md)を受け、既存の運用定跡に
沿った駒組みの先で、固定した学習候補と現行版を比較する。

## 実行

準備済み。リポジトリのルートで実行する。

```sh
python3 -m tools.learning.constraints.book_match run
```

出力先は `results/learning-pilot/2026-10-18-projected-book-match-v1/`。
`summary.txt`、`report.json`、`games/` に結果と毎手の記録を保存する。
prepare・export・ビルドは不要。完了局は再実行せず未着手局から再開する。
途中中断・失敗の場合は記録を保持して停止するので、ログを確認して対応する。

## 開始局面の固定方法

他項目の親手順に続くものを除き、残る７本をすべて採用する。
評価値・探索・勝敗による選別はない。定跡の相手側の手も既存の記録どおりに使用する。

完全な手順・SFEN・入力とコードのSHAは出力先の `plan.json` に固定する。
７局面同士は盤面・持駒・手番で比較し、180度回転＋先後交換も含め非重複を確認。
末端が別の定跡登録局面に直ちに合流していないことも確認した。
今後の対局途中の合流はありうる。過去データとの非重複・独立性は主張しない。
特に後手５本は同じ四間飛車系の近い分岐なので、合計勝敗だけでなく入口別に見る。

## 条件と判断

候補は従来のprojected-search固定200更新版、相手も従来の現行版。
両者新米長玉ON、定跡OFF、Threads1、Hash64、depth15、watchdog300秒。
各入口で候補の先後を交換し計14局。各局で両エンジンを新規起動する。
指定手順の終了から追加256手を上限とし、未決着を引分けに置き換えない。
正式な反復・連続王手・宣言等は従来のnative refereeで判定。
エラー・timeoutを敗戦にしない。

定跡は開始手順の出典として使い、対局中の定跡機能は使わない。
初期局面からの運用全体や、定跡分岐の選択性能を測る試験ではない。
同深さは同時間でもない。以前の９勝５敗２未決着、７勝８敗１分とは別に記録する。
開始手数と新米長玉側の内訳も異なるので、単純な勝率の上下で原因を断定しない。

結果確認では入口別・候補の先後・新米長玉側を分け、厚みについては指定手順の後に
候補自身が選んだ支えや銀の進出を見る。定跡で与えた配置を学習成果に数えない。
好結果でも即採用せず、不調でも有利な入口への差替えはしない。
