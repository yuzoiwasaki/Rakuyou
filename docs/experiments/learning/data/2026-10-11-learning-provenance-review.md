## 確認できたこと

`tools/audit_learning_provenance.py` で、準備manifestが参照する生JSONと
train/validation/testの現在のSHAを再確認した。
対象47run・2,740局の生JSONハッシュは、過去レポートの保存値とすべて対応した。
対象から外したsmoke2run・4局はこの確認の件数に含めない。
各runの参照レポート・行番号・レポートSHAは別の照合JSONに保存した。

通常はファイル名とその近傍のSHAを照合する。例外の先手pawn26試験2runは、
[先手報告](../../books/black/2026-10-03-black-300-game-branch-review.md) の
「先手固定200局の結果」の表にある `trial-r1` / `trial-r2` の短い実行名と
保存SHAを対応させた。他の試験の同名ラベルは採用していない。

| 確認項目 | 結果 | 証拠の範囲 |
| --- | --- | --- |
| 生JSON | 47/47run、2,740局で保存SHAが対応 | レポートに記録された生データとの対応 |

## バイナリと評価データを分ける

先手定跡対応の `433f8d0` では、`src/` の変更は `shin_book.cc` の
先後制限解除だけだった。評価・探索・学習のソースは変更していない。
このビルドのSHAは
`6f7891c4957e1bf37b1e80c37ad0c9cf83f34ca974e87be05fb05dd5c1f4c2ac`。
[先手比較の準備と結果](../../books/black/2026-10-03-black-300-game-branch-review.md) に
明示され、その後の[先手独立レビュー](../../books/black/2026-10-10-black-book-independent-review.md)でも
同じバイナリを使ったことを記録している。

後手v2の200局比較は、先手対応前の系列で、
[後手レポート](../../books/white/2026-10-03-v2-bounded-white-improvement-cycle.md)に
`a1a5e25ada0d7be1375b45168586f00f7feaa29f1a87074a85b0e4b09c571f1b`
を解析・動作確認用バイナリとして記録している。
この記述を全対局プロセスの起動時証明に読み替えない。
古い先後交代データは、当時のバイナリハッシュの自動記録がないことも
レポートに明記されている。全47runを同じ実行バイナリで生成したとは扱わない。

`bin/params.bin` / `progress.bin` / `probability.bin` はGit管理外である。
過去のソースが変更されていなくても、ローカルでデータを差し替えた可能性は
Gitの履歴だけでは検査できない。過去レポートに「従来値と同じ」とある対象は
主にエンジン・標準定跡・専用定跡であり、3つの評価関連ファイルについての
当時の完全なSHA記録として代用しない。
現在の3ファイルのハッシュが過去レポートに記録されている箇所は、
今回作成した学習調査記録以外には見つからなかった。

このため、照合JSONでは過去の評価関連SHAを `null` のまま保持する。
生JSONのハッシュ対応が確認できても、`training_ready` は自動でtrueにしない。
準備済みmanifestやJSONLのフラグも変更していない。

## 次の実装へ持ち越す条件

- 「過去runのparamsが現在と同一」は未証明の仮定として残す。
  現行評価から過去の探索cpを学ぶ場合は、由来にこの制約がある歴史的教師として
  入力manifestに明示する。現在のparamsから生成した教師とは表示しない。
- 初回の更新なしのreader・評価検証には、由来が暫定である集合も利用できる。
  学習損失や更新の入口と区別し、ここで学習可能フラグを解除しない。
- 学習用の集合を確定するときは、文書で支えられる比較系列を優先する。
  例えば先手pawn76/pawn36の4runと後手v2比較の4runは、各生JSON・条件・
  バイナリ系列の参照先を追いやすい。現行paramsとの同一性まで確定した8runではない。
- 将来新しく教師や対局を生成する前に、起動時の実行ファイル、params、progress、
  probability、定跡のSHAとソースHEADを自動保存する。
  本レビューのために新しい対局や探索を追加しない。
- 最初の24手を越える長い共通手順と正式な結果裁定は、この由来確認では解決しない。
  特に上限drawの勝敗マスクと後手drawの診断層は維持する。

次は**更新なしの学習入力readerと固定ベース／差分の検証入口**を準備する。
非ゼロ差分の適用、勾配更新、学習実行、現行データへの昇格は引き続き別段階とする。

## 再現と検証

```sh
python3 -m unittest discover -s test -p test_audit_learning_provenance.py -v
python3 tools/audit_learning_provenance.py \
  results/learning-pilot/2026-10-11-preparation-v2/manifest.json
```

`--output` を付ける場合は未使用のファイル名を指定する。既存ファイルへの上書きは拒否する。

分割ファイル改変の拒否、過去データSHAを推定で埋めないことを確認した。

`44704fc910fc3217a55399951d6a60ab233a49b80b0a017695e7672627954792`。
