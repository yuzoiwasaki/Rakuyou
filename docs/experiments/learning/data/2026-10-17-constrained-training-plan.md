# 上限内で方向を変える更新器：旧方式との比較

[境界診断](2026-10-17-constraint-direction-audit.md)を受け、別モジュールに継続学習用の
更新器と比較runnerを実装した。現行エンジン、元のhybridコード・閉じた実験は変更しない。
まず「同じ上限でも、別方向に進めると学習がどう変わるか」を調べる。
新米長玉の個性を直接教える教師を追加した実験ではない。

## 実行

準備済み。リポジトリのルートで次を実行する。

```sh
python3 -m tools.learning.constraints.runner run
```

出力先：`results/learning-pilot/2026-10-17-constrained-training-v1/`。
prepareや教師生成、ビルドの再実行は不要。新しい探索・対局は行わない。
６試行の学習とnative静的評価を行う。実行時間は未計測。
各完了更新を保存するため、中断後は同じコマンドで最後の保存地点から再開できる。

最後に `summary.txt` と `comparison.json` を生成する。
各 `legacy-探索方式名/`・`direction-探索方式名/` にcheckpoint、停止診断、評価を保存。
方式名は `search`・`outcome`・`mixed`。サマリーに勝敗予測と探索教師への誤差改善、
更新回数、停止理由、検証の最大変化量を表示する。改善率は勝率ではない。

## 固定した比較条件

| 項目 | 設定 |
| --- | --- |
| データ | 既存の共通学習255・検証63局面。同じ保存教師 |
| 更新器 | legacy（旧方式）／direction（新方式） |
| 教師 | 探索のみ／勝敗のみ／半々混合、両更新器で計６試行 |
| 初期値 | 全試行ゼロ差分。旧最終候補からの継続ではない |
| 予算 | 各最大200更新。検証結果による早期停止・選び直しなし |
| 学習目的関数 | 既存の交差エントロピーとL2=1e-6 |
| 変化量上限 | 学習局面100cp、係数0.5cp。旧方式と共通 |
| 基準歩幅 | 0.02、バックトラック最大20回。旧方式と共通 |
| 観測 | 全６試行終了後に、既存469局面をnative／丸め前の両方で評価 |

旧方式は最初から再計算し、元の３checkpointと係数・全更新履歴・更新回数・停止理由が
完全一致することを確認する。不一致なら比較を止める。
保存checkpointは停止理由の診断に使用するが、新方式の初期値・更新判断には使わない。
検証63局面は既に見た診断集合で、独立した最終試験ではない。

## 新更新器の動作

1. 学習データだけから勾配を計算し、既存と同じ最大成分で正規化する。
2. 上限まで1e-6cp以内の局面・係数を境界として、外に向かう方向成分を順に除く。
   複数の制約が干渉すれば繰り返し、最大1000巡で止める。
3. 修正後の方向が誤差を減らす向きであることを確認する。全局面・全係数について
   上限までの歩幅を計算し、その99%以下かつ基準歩幅以下にする。
4. 実際の仮更新について上限を厳密に確認し、学習目的関数が十分に減った場合だけ採用。
   減少条件は方向微分に対するArmijo係数1e-4と厳密な減少の両方。
   条件を満たさなければ歩幅を半減する。最小歩幅1e-12。

方向の残差許容値1e-10は方向修正の終了判定にのみ使う。更新後の100cp／0.5cp上限を
超えてよいという許容値ではない。方向修正後も１係数あたりの基準歩幅を超えないよう
必要なら正規化する。試作と同様、厳密な最短距離射影ではない。

停止理由を `zero_gradient`、`direction_iteration_limit`、`no_descent_direction`、
`step_too_small`、`no_acceptable_improvement`、`update_budget` に分ける。
後ろへ進めなくなっただけで「最適解へ収束した」と報告しない。
境界が増えると新方式も止まり得る。その理由と改善量が今回の観測対象である。

## 判断すること

第一に、旧方式の停止地点を超えて制約内で改善できるかを確認する。
単に更新回数が増えるだけでは成功としない。学習・検証それぞれで、勝ち群と負け群、
先後、両教師への誤差、最大変化量を見る。引分けは学習から外した従来の診断として別記する。
学習誤差だけ減って検証が悪化するなら、そのまま棋力改善候補とはしない。

soft penaltyや上限増加は今回同時に変えない。新方式で境界内の改善余地を使えるかを
先に確かめ、改善方向が見つからない／継続が不安定な場合に検討する。
比較後も自動export・対局・候補選択・現行評価への採用は行わない。
生成するdelta.txtはnative静的評価用の差分で、運用params.binへの書込みではない。

## 準備時の確認

- 全体349テスト通過。その後、方向修正の反復上限を確認する１テストを追加し、
  新更新器の８テストを再実行して通過。監査用４テストと合わせ、新領域は12テスト。
- 複数境界での反復更新、正負の境界、係数上限との干渉、非有限値・不正入力、
  方向がない場合、最小歩幅、途中中断からの同一結果への再開と完了後の再実行抑止を確認。
- 実データの保存最終checkpoint３件で、新実装の仮１ステップが両上限内で改善することを
  確認。仮係数は保存せず、反復学習は行っていない。
- nativeで469局面のゼロ差分評価が元の評価に一致。入力・runtime・コードの結び付けを確認。

全設定を記録し、実行時・終了時に確認する。
