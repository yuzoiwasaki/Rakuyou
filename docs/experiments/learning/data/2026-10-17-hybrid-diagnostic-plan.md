# 負け２局面の同条件探索：実行手順

[保存棋譜レビュー](2026-10-17-hybrid-match-loss-review.md)に基づき、第７局79手目直前
（先手番・履歴78手）と第４局88手目直前（後手番・履歴87手）を固定した。
前者は金打ちの王手を含む戦術、後者は玉への攻めを読んだうえでの攻防評価を調べる。
結果を見て選んだ診断局面であり、棋力測定や新しい正解教師ではない。

## 実行

準備済みなので、リポジトリのルートで次だけを実行する。

```sh
python3 -m tools.learning.playtest.diagnostic run
```

出力先：`results/learning-pilot/2026-10-17-hybrid-diagnostic-v1/`。
`summary.txt` に各探索の指し手・表示深さ・評価・注意点、`searches/` に
読み筋・全通信ログ・失敗記録、`report.json` に集約結果を保存する。
準備コマンドやビルドの再実行は不要。

## 条件と実装

- ２局面 × 要求深さ15・20 × 現行版・固定済み探索教師候補＝８探索。
- 各探索で新規プロセス。全着手履歴を渡し、対局中のハッシュ状態は引き継がない。
- 新米長玉ON、定跡OFF、Threads1、Hash64、MultiPV1。候補手の指定なし。
- １探索のwatchdogは300秒。`go depth` を用い、持ち時間制の比較ではない。
  探索待ちだけの上限は計40分、別に起動・検証処理がある。深さ20の所要時間は未計測。
- 正常なbestmoveと、timeoutでstopした結果を区別する。最後のinfoが要求深さより
  浅い場合やbestmoveとPV先頭が違う場合は明示する。表示評価を最終指し手の
  正確な評価として扱わない。通常手とPVの合法性はnative refereeで確認。
- 完了した成功・失敗は再実行しない。通常のtimeout等は保存して残りの探索へ進む。
  強制終了等で結果のないattemptだけ残った場合は再実行を止め、記録を確認する。
- 元の対局・学習コードとruntimeは変更しない。新規`diagnostic.py`のみで実行する。
  元対局のplan/runtime/source、選択棋譜、診断コードをチェックサムで結び付ける。

攻防と見積りがどう変わるかを確認する。ただし別の指し手なら同じ筋が現れる必要はない。

判断を続ける場合を分ける。差が不安定なら、この２例を掘り続けない。
