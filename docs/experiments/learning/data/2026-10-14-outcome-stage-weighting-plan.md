# 次の勝敗学習案：進行度で最終結果の重みを変える

2026年10月14日。データ拡大・20更新・[負け局面診断](2026-10-14-outcome-loss-position-review.md)を
コミット `9186105` に保存した後の相談案。実装・学習・探索はまだ行っていない。

## 何を変えるか

現在は序盤の途中局面にも、中盤の接触した局面にも、最終勝敗を同じ強さで与える。
次は勝ち棋譜も負け棋譜も残し、序盤寄りの局面は最終結果から少し弱く学び、
局面が進むほど重く学ぶ案を第一候補にする。
同じ383／80元局面、決着256／64、別枠後手draw6を使い、局面を選び直さない。

| 案 | 将棋での意味 | 必要な変更と限界 |
| --- | --- | --- |
| 既存の進行度で重み付け | 駒組みの形に最終敗戦の責任を強く負わせず、進んだ局面を相対的に重くする | 保存値と重み付き損失のみ。進行度は悪手や敗因を示す値ではない |
| 投了までの残り手数で重み付け | 決着に近い局面を重くする | 棋譜から得られるが、投了の早さや勝者の寄せ方にも左右される |
| 探索評価と勝敗を混ぜる | その場の形勢判断と最終結果の両方を教える | 混合比・教師尺度が増える。過去探索はruntime不明、現行探索の教師生成には時間が必要 |

第一案は教師生成を増やさず、勝敗学習の路線を維持できる。
本家にも勝敗と探索教師の別の学習項があるが、現在の簡易runnerへ混合機能がそのまま実装済みという意味ではない。
参照：`src/learning.cc` の `ComputeGradientOfRootStrapLoss` / `ComputeGradientOfLogisticRegressionLoss`。

## 一度だけ試す場合の固定条件案

保存済み元局面の進行度p（0～1）に対し、基本重みを `w = 0.25 + 0.75*p` とする。
この式は設計上の仮置きで、検証成績から選んだ値ではない。結果を見て傾きや下限を調整しない。
予測値から進行度を再計算せず、既存の保存値を固定する。

学習側256件だけの保存値を確認したところ、pは約0.195～0.820、基本重みは約0.396～0.865。
ただしそのまま使うと、勝ち128件の重み合計79.441、負け128件は75.756となる。
勝ちを相対的に重くする変更が混ざるので、学習の先手勝ち・先手負け・後手勝ち・後手負けの
4層それぞれ64件について、重みをその層の平均重みで割る。
これにより各層の総重量64、全体256を維持し、層内で進行度による重みだけを変える。

| 学習層 | 基本重み平均 | 正規化後の最小～最大 |
| --- | ---: | ---: |
| 先手勝ち | 0.61710 | 0.648～1.390 |
| 先手負け | 0.60807 | 0.656～1.356 |
| 後手勝ち | 0.62417 | 0.653～1.364 |
| 後手負け | 0.57563 | 0.689～1.503 |

損失は各局面の交差エントロピーを正規化重みで掛けて256で割り、従来と同じ差分L2を加える。
勝敗ラベル0／1と `sigmoid(cp/600)`、学習キー、KP／PP、ゼロ差分開始、L2=1e-6、
20更新、step/cap/平均化、固定20平均候補を維持する。
上限drawは引き続き勝敗学習から除外し、影響確認だけに残す。

検証の重みは変更せず、従来と同じ等重みの全体・先後・勝敗各層の誤差で比較する。
整数化前と後を併記し、元の等重み学習損失も確認する。
局面全体差とdrawへの影響、保護項目・上限の監査を維持する。
旧runner・候補・結果・markerは変更せず、新しい実験として分離する。
必要なテストは重み・勾配・4層の総重量・draw除外の確認に限定し、一般的な設定機構は作らない。

## 期待と判断の限界

試す目的は「負けを外す」ことではなく、途中の配置と最終勝敗の結び付けを少し弱める有用性の確認。
今回の診断だけでこの変更が負け側の悪化を改善すると予測できない。
共有するPP配置への加点偏りや、具体的な攻めを静的評価が表し切れない問題は残り得る。
候補変更は小さいため、20更新で差が乏しい可能性もある。

検証集合は既に層別成績と4棋譜を見ており、今回の案にもその診断を使っている。
同じ検証で良くなっても、未見局面での強さの証明にはならない。
結果が良くても現行評価へ自動採用せず、追加調整・学習延長・候補選び直しは行わない。
実装と一度の学習へ進むかは、この案を相談してから決める。
