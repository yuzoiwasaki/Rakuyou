# 中央の歩の支え：更新0の準備とL2・評価差の監査

2026年10月12日。[少数棋譜での比較と出現数](2026-10-12-supported-pawn-thickness-review.md)から、
中央３〜７筋・五段目の生歩を同じ側の金または生銀が直接支える1特徴を実装した。
歩1枚を1回だけ数え、幾何学的な利きを使う。ピンや利き数による除外は加えない。

既存143／35件の教師・固定末端を再利用し、更新0の状態保存と監査まで完了。
学習、教師再生成、静止探索、通常探索、対局、運用採用は行っていない。
目的は現行評価の教師に対する有用性の観察で、加点する符号は強制しない。

## 実装と保全

- `tools/learning/native/supported_pawn_probe.cc`：既存の局面再生・合法手・評価データ読込・
  端数処理を利用する静的probe。独立した `results/supported-pawn-tools/supported-pawn-probe` に出力。
- `tools/learning/gold_silver/supported_pawn_preparation.py`：既存の損失・更新器の初期状態・
  checkpoint・独立バックアップを利用する準備専用の入口。`--run` は提供しない。
- `src/`、通常release、評価データ、定跡、25cp補正、旧probe・候補は変更しない。

旧実験のソースパスはディレクトリ整理前のものなので、終了済みrunnerを再実行しない。
既存教師生成レポート・監査、末端レポート・監査を既知のSHAで固定し、保存JSONL／frameの
一致、元棋譜のSHA、教師入力コピー、現行runtimeを照合した。
新しい準備で使う現行ソースと保存物を別のbindingに記録し、過去の監査メタデータは書き換えない。

今回使ったビルド・準備コマンド：

```sh
make supported-pawn-probe -j2 object_dir=results/layout-build-check/obj
python3 tools/learning/gold_silver/supported_pawn_preparation.py \
  --output results/learning-pilot/2026-10-12-supported-pawn-preparation-v1
```

出力は新規ディレクトリのみ。190ファイル、697,558,391 bytesを既存のバックアップ機能で
独立コピーし、保存前後のSHA・inodeを確認した。同一ボリュームのローカルコピーであり外部バックアップではない。

## 固定する実験条件案

| 項目 | 条件 |
| --- | --- |
| 基準 | 現行評価。初期差分 `[0,0]`、手番・安全度・金銀連結候補は混ぜない |
| 係数 | 先後共通の序盤・終盤2係数。各1単位は支えられた中央の歩1枚、cp単位、符号自由 |
| 補間 | `(1-progress) × 序盤 + progress × 終盤`。先手数−後手数を掛ける |
| 集合 | 教師・固定末端143／35件。test使用なし、補充・再生成なし |
| 更新 | 将来実行する場合は一度だけ20回。batch128、seed20261011、保存0／5／10／20 |
| 更新器 | 既存RMSprop。rate／1更新上限0.05cp、decay0.9975、epsilon10⁻¹²、平均decay0.9995 |
| 制約 | 各係数±0.5cp、元局面・末端の整数評価差±10cp以内。上限到達も記録する |
| L2 | 10⁻⁶。学習側の初期勾配と単位で確認し、検証品質を見る前に固定 |
| 候補選択案 | 保存0／5／10／20のうち、評価差上限内で検証の整数評価が変化し、平均損失＋L2が基準より改善する候補。最小値、同値なら早い更新を選び、該当なしは0 |

更新器は既存の8スロットを利用し、最初の2スロット以外は0のまま。
準備planの `training_enabled`／`deployment_enabled`／勝敗損失はfalse。
保存したゼロ候補はsidecarで、現行エンジンが読み込む評価ファイルではない。
候補選択案は前回と同じ方法で、実行を承認する際に実行用計画へ記録する。準備planは書き換えない。

## L2と数値監査

学習143件で、初期差分0のデータ勾配は序盤−3.4664187500×10⁻⁶、
終盤−5.9174604706×10⁻⁶。初期の平均sigmoid二乗損失は0.01170461224。
L2が係数上限0.5cpで加える勾配は5×10⁻⁷で、初期データ勾配の約14.4％／8.45％。
今回の単位では初期信号を正則化が直ちに打ち消すほど大きくない。
学習中の勾配減少・相殺や整数丸めによる小さな変化はあり得る。結果を見てL2を再調整しない。

序盤・終盤の2列は学習集合上で独立。初期0と数学的差分 `[0.01,-0.01]` で
解析勾配と有限差分を照合し、最大絶対誤差は8.41×10⁻¹⁶以下だった。
これは更新器を進める学習ではない。

基準のnative再生178件で、保存末端のSFEN・評価・進行度・評価内訳が全て一致。
元局面・末端356箇所の特徴数も独立したPythonの幾何学的な数え方と一致した。
ゼロ候補の元局面・末端の評価差は全件0。旧金銀連結の更新0候補が記録した
同じ178件の基準cp／元局面cpとも一致した。

係数の静的差分 `[0.25,-0.25]`、`[-0.25,0.25]`、上限の `[0.5,0.5]`、
`[-0.5,-0.5]` で、nativeの整数化と滑らかなモデルを照合。
KP・手番・無関係のpacked laneが保護され、指定laneに個数差×差分だけ加わることを確認した。
学習・検証の元局面と末端における整数評価差は全4組で最大1cp。
この集合の片側最大個数は2なので、係数上限での滑らかな差分は最大1cpとなる。

固定末端の出現数は学習49／143、検証10／35。先手の歩は27／5、後手の歩は22／5。
先後・draw各層は[出現表](2026-10-12-supported-pawn-thickness-review.md)のまま。
検証の先手負け層は0／6であり、層別の有用性には大きな制約がある。
検証損失・候補の品質は今回測定していない。

新規テスト4件で、複数金銀での重複計数、３・７筋の境界、範囲外／成駒の除外、
先後の回転対称性、実際の利きと近さの区別、改変入力／既存出力／bin出力の拒否、係数上限を確認。
既存の勾配・更新上限／checkpoint・独立列の数値テスト3件も通過した。
新規probeのビルドは成功し、既存ヘッダー由来の警告が出た。
