# 合法手ゼロの局面で確率計算を呼ばない修正

[修正後比較](2026-11-01-repaired-search.md)で残った6件の停止は、
`ComputeProbabilitiesWithCache` が合法手1件以上を要求するassertだった。
第02局64手目・加点0で診断探索を1回実施し、停止時SFENを取得した。
保存局面は `Position::IsOk()` が成立し、王手中で合法手0件。
この局面は回帰テストに固定した。診断は比較結果の補充ではない。

## 原因と修正

`MovePicker` は深さ8以上で、王手中でも確率順の指し手生成を選ぶ。
合法手を生成・フィルタした後、空でも確率計算を呼んでいた。
深さ8未満の王手回避経路ではこの確率計算を行わない。

`GenerateNext` の確率生成段で合法手0件なら直ちに戻る。
次段で `NextMove` が既存の終了処理に従って `kMoveNone` を返し、
探索側の既存の詰み／打ち歩詰め判定へ進める。
確率計算関数のassertは残す。詰みスコアや評価項を変更しない。

## 検査

- 修正前のMovePickerをリンクした対照バイナリで、保存局面のみから
  `move_probability.cc:699` の同一assertを再現。
- 修正後は先後反転の双方で、深さ7・8・9の6条件を通過。
  深さ7では疑似合法の王手回避手を探索側同様に合法性で確認し、全て不合法。
  深さ8・9では最初から手なしを返す。繰り返し呼び出しも手なし。
- `make movepick-terminal-test` と
  `results/move-feature-tools/terminal-test bin/params.bin` で実行可能。
- 最初のテスト案は浅い生成器も合法手のみ返すと誤って仮定して失敗。
  浅い生成器の仕様に合わせて上記の検査に修正し、旧実装の同一assertを確認した。
- O2/assert有効の隔離ビルド。運用バイナリ・評価データは変更しない。
