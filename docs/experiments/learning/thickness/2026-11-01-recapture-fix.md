# 仮想的な取り返し処理の停止を修正

厚みの[比較実験](2026-11-01-support-chain-search-result.md)で発見した
`Move::IsOk()` 停止を、保存局面だけの特徴抽出で再現し、修正した。
トークン切れや実験の中断に依存しない既存コードの不具合だった。

## 原因と変更

`ExtractMoveFeatures` は駒を捨てた後の相手の取り返しを仮定する。
旧処理は最も安い攻撃駒の種類を求めた後、実際の攻撃駒に限定せず
同じ種類の駒から移動元を選び、成りも常に無効にしていた。

固定した失敗例 `fixed-03-64` の `P*9i` では、後手の9cの香が取り返せるが、
旧処理は1aの香を選び、9iへの不成を作って停止する。
修正では実際の攻撃駒から移動元を選び、歩・香の最終段、桂の最終２段では成る。
攻撃駒がなければ取り返し後の特徴を追加しない。
これは特徴抽出の幾何学的な仮定であり、ピンや王手放置を調べる合法手生成器ではない。
任意の成りを最適化する変更は含めない。

## 確認

- 修正前のコードで、保存SFENと `P*9i` の特徴抽出だけで同じassertを再現。
- 修正後は同じ特徴抽出が成功。
- 歩・香・桂の強制成り、任意成りの維持、成駒、最安駒の選択、
  無関係な同種駒の除外、先後反転の18例が成功。空集合も確認。
- 同じ失敗ルートで新規プロセス、加点0/10各１回、深さ9、thread1、hash64、
  bookOFF、ShinON、30秒上限のスモーク探索が両方完了。
  両方 `S*5e`、-355cp、17678 nodes。双方のPVをネイティブに合法手再生できた。
- O2・assert有効の隔離バイナリを使用。運用バイナリ・評価データは変更していない。

再利用する検査は `make move-feature-recapture-test`、
`results/move-feature-tools/recapture-test bin/params.bin`。
診断コード・ログ・計画・探索結果はローカルの
`results/thickness-dialogue/recapture-debug-2026-11-01/` に保存した。
