# 支持関係の試験項：既定無効で実装、探索前の照合を完了

2026年10月31日。ユーザーは相談局面A59を部分的な厚みと認め、
相手の攻め駒を厚みでうまく抑えている形と説明した。
これを受け、敵の攻撃があることだけでは除外せず、設計した計数を評価へ接続した。
新しい探索・対局・学習は行っていない。

## 変更

- `Evaluation::HasPawnSupportChain` が２〜８筋の五段目の歩と、その自陣側の金銀、
  さらにそれを自陣側または同段から支える金銀の関係を判定する。
- `ExperimentalSupportChainBonus` は既定0、範囲0〜10。両側の有無の差に係数を掛ける。
  進行度pで `(1-p)` に減衰し、手番項・進行度の重みは変更しない。
- 全評価と差分更新に独立項を加え、probeの評価内訳にも含めた。
  `EvalParameters` の構造と保存ファイルの形式は変更していない。
- 設定は検索ノードを作る前に行う。比較は毎回別プロセスとし、設定変更前の
  評価キャッシュや置換表を使い回さない。

10cpは試験値であり、ユーザーの局面採点ではない。
この特徴は厚み全体の判定でも、位の安全性や交換有利の保証でもない。

## 確認

計数監査42局面とその先後反転42局面で、Python版とnative版の両側の値が一致した。
14本の保存対局と過去の反例３本、合計2,508手を0/10の両設定で再生した。
各手で全評価と差分評価を照合し、巻き戻しと可能な末尾局面でのnull moveも検査した。
支持関係が変わる手、駒の交換、成りを含む実戦手順上で差分更新の一致を確認した。

加点によって進行度が変わらないこと、通常の整数評価との差が最大10以内であること、
丸め前の予定値との誤差が整数切捨ての範囲内であることも確認した。
ゼロ設定の17本の終点評価は、改変前の保存済みlearning-data-probeと一致した。
全ての可能局面での同一性や探索結果の一致を証明する検査ではない。

独立した試験用エンジンを作成し、USIの既定値・範囲と10設定でのreadyokを確認した。
`go` は送っていない。運用の `bin/release` と `bin/params.bin` は書き換えていない。
試験ビルドはassert有効のO2であり、運用releaseとの速度比較には使わない。
今後の0/10比較は同じ試験バイナリ同士で行う。
