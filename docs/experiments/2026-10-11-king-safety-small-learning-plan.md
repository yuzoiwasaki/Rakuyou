# 玉周囲8マスの小規模学習案：金銀の厚みへの第一段階

2026年10月11日。手番3係数の実験は終了し、候補を運用採用しない。
次は既存の玉安全度評価を基準に、玉周囲8マスの少数共有差分を実際に学習する方針とする。
この文書は実行前に固定した案。[初回20更新の結果](2026-10-11-king-safety-first-pilot-result.md)を参照。
現行評価への採用は結果を見て別途判断する。

## 何が分かり、何がまだ分からないか

目標は、玉を囲うことだけでなく、金銀が支え合って前へ出る新米長玉らしい厚み。
今回調べるのは、その土台となる「玉に近い金銀に支えがあるか、近傍で利き負けしていないか」。
前に出た金銀が玉の隣接範囲にあり、味方に支えられていれば状態の違いを拾える。
玉を囲うために金銀を寄せることや前進自体に固定ボーナスを付けない。

| 今回の特徴 | 評価できる状態 | 今回の限界 |
| --- | --- | --- |
| 守られた金 | 玉に隣接した金に、玉以外の味方の利きがある | 支えが銀か歩かなど、支える駒の種類は区別しない |
| 守られた銀 | 同条件の銀。金との役割差を学ぶ | 金銀相互の支えを特別扱いしない |
| 孤立した金銀 | 玉に隣接した金銀に、玉以外の守りの利きがない | 玉から離れた浮き駒は対象外 |
| 隣接マスの利き負け | 玉の隣接マスで敵の利きが守りより多い | 正確な詰み・合法な逃げ道・攻撃成果を直接表す特徴ではない |

既存評価の相手持ち駒や方向別の細かい安全度は基準として残す。
今回の共有差分では、前進の方向・2段目の金銀配置・連結の長さ・攻撃参加の価値を新しく表現しない。
利きは既存ExtendedBoardの定義を使い、玉の利きを守りから除く。
「守られている」を必ず良いと決めず、残差の重みを教師から学ぶ。

次の厚み段階では「金を銀が支える／銀を金が支える」「相互に支える」「玉から2マス程度の
範囲で連結を保って前進する」を別の特徴として追加する案へつなぐ。
今回は支える駒の種類を区別しない基礎を確認し、その後に支えの種類・距離・前後方向を分ける。
この最初の実験で厚み全体を学習できたとは扱わない。

## 実装範囲

`src/evaluation.cc` の `EvaluateKingSafety` と `src/evaluation.h` の `king_safety` tableを使う。
玉周囲8マスの駒、攻めの利き、玉を除いた守りの利き（最大3）をそのまま活用。
初期差分0で現在のtableを固定ベースにし、該当entryへ4特徴の共有差分を加える。
新しい安全性の枠組みや追加のUSI切替、汎用学習基盤は作らない。

- 守られた金／銀は自分の未成の金／銀で守りの利き>0。
  孤立は同じ金／銀で守りの利き=0。成銀・と金等の金と同じ動きの駒は最初の特徴から除く。
- 利き負けは盤内マスで攻めの利き>守りの利き。盤外wallは差分を加えない。
- 4特徴×序盤／終盤＝8係数。packed scoreの0／2成分だけを変更し、
  手番依存の1／3成分、進行度、駒価値、KP／PP等、手番係数は固定する。
- 双方の玉に同じ特徴を適用し、色反転・右玉の左右反転は既存規約を使う。
  重なる特徴の差分は加算する。既存の評価項目との重複は残差学習として扱う。
- 共通の安全度tableへの差分なので、候補paramsを使うON／OFFの両方に作用する。
  今回の学習・候補評価はShinYonenagaGyoku ONで行う。運用は元paramsのまま。
  ONにだけ適用する新しい評価コードは今回導入しない。

必要な追加は、native probeの特徴出力と手動差分評価、8次元の目的関数／更新器接続、
king_safetyの許可entry／成分だけを変える別名exporter、実験runnerと必要な検査に絞る。
既存のSHA照合・独立コピー・checkpoint・backup・PV合法性・整数再評価・損失・候補選択を再利用する。
既存3係数ツールと過去キャッシュは変更せず、閉じた手番実験を再実行しない。

## 最初の実学習条件案

| 項目 | 提案 |
| --- | --- |
| 入力 | 由来確認済みのtrain36／validation18とその基準固定QS末端を再利用 |
| 開始状態 | 運用中の基準params＋安全度8係数のゼロ差分。手番候補はベースにしない |
| 教師 | 現在の基準depth15 cp、ルート手番側。勝敗損失OFF、後手draw由来も保持 |
| 損失 | mean sigmoid-square、gain1/600、差分L2=1e-4 |
| 更新 | 最大20回、全train36件、seed20261011、RMSprop／平均化は既存方式 |
| 係数上限 | rate／単回最大0.05cp、各係数の総差分±0.5cp |
| 保存 | 0／5／10／20の平均化候補と完全な状態を別名保存 |
| 選択 | validation整数損失＋L2が基準より1e-12超低下し、整数評価が変化した候補。改善なしなら基準 |
| 運用採用 | 自動では行わず、結果を見て別途判断 |

特徴が1局面で複数回出るため、手番実験の±5cpを流用しない。
最初は係数の差分を±0.5cpに抑え、使用54ルートと固定末端の最終整数評価差が±10cpを超えた候補は
採用候補から外す。超えた局面だけを除いて学習を続けることはしない。
この上限は評価変化の抑制であって、棋力や安全性の保証ではない。

新特徴の出現・非出現、色別／run別分布、8列の識別性をtrain36件でまず確認する。
未出現・同一列等で識別できない自由度はゼロに固定して残りの係数で小さい実験を行う。
validationの損失を見て特徴・上限・正則化を選び直さない。
54件・自己蒸留は動作と限定した学習効果の確認用で、強化を証明するデータ量ではない。

## 一まとまりで進める手順

1. native特徴抽出と許可entry／成分の定義を実装し、既存54末端を新探索なしで再生して特徴を得る。
   色反転・左右反転・wall・玉を除いた守り、ゼロ差分の完全一致、整数評価との接続を検査する。
2. 8係数の更新と限定exportを接続し、必要な勾配・丸め・変更範囲検査と更新0の保存／復元を行う。
   手番実験で使った同じ検査基盤を必要範囲で使う。
3. train上の出現分布と識別性を踏まえて自由度を確定し、上記小さい条件を固定して20更新を一度実行。
   保存・validation比較・結果監査までまとめる。条件内で実行できない場合は理由を報告し自動拡張しない。

新しい教師探索や大規模な棋譜収集、2段目特徴、対局・testによる検証を今回は含めない。
固定末端の候補比較と通常探索での動作は異なるため、採用判断に追加の観察が必要なら
結果を見て別の範囲を相談する。未使用test224件を使った合わせ込みはしない。

現行評価・定跡・25cp補正を維持し、手番3係数の実験には戻らない。
