# 初期局面からの先後２局

目的は、新米長玉support10＋D10の序盤に明確に不自然な手順がないかを見ること。通常Rakuyou（新米長玉OFF/support0/D0、従来の固定通常版）を相手に、先後を入れ替えて１局ずつ行う。元のGikou2との同一性や棋力同等性は未検証。

両局とも空の指し手履歴から開始し、途中局面や戦型を指定しない。双方の定跡はOFF。採用版の既存処理により、自分の最初の一手だけは先手▲４八玉・後手△６二玉に固定される。その後は通常探索。GUI既定の定跡ON運用とは区別する。専用定跡ファイルは起動に必要なので配置するが、指し手選択には使用しない。

- 採用側：新米長玉ON・support10・D10。
- 通常側：新米長玉OFF・support0・D0。
- 双方：深さ15上限、秒読み10秒、1スレッド、Hash64、Ponder OFF。
- 最大256手。各局で新しいエンジンを起動し、実験用RAKUYOU環境変数を除去。
- 過去の対局と合算しない。２局で棋力や先後差を判定しない。

## 実行

リポジトリ直下で：

```sh
caffeinate -i python3 -u docs/experiments/startpos-pair-2026-11-14/match.py run
```

準備と動作確認は実施済み。本対局は未実行。目安１時間前後、両局が最大手数まで続けば約85分＋処理時間。

Ctrl+Cを１回押すと現在の局を終えて停止する。同じコマンドで完了済みの局を飛ばして再開できる。２回目は即時中断となり、不完全な局の自動再試行を禁止する。エラー時はログを残して確認する。prepare/preflightを再実行しない。

進捗は別ターミナルで（１局終了ごとに更新）：

```sh
cat results/teatsui-startpos-pair-2026-11-14/summary.txt
```

終了時のCompleted 2/2以下の集計を共有する。勝敗にかかわらず明確な受け不足・無理な支持・駒の遊びなどを優先し、問題が曖昧な局は深追いしない。

## 検証と保全

９項目のテストで先後・再開・失敗停止・環境変数除去・時計・初手固定から通常探索への移行などを確認。実バイナリの８回の接続確認は、通常探索６回（深さ３）と既存初手固定２回。すべて合法性をネイティブ判定器で確認する。初手固定には探索評価値や探索時間が出ないため、通常探索と区別して記録する。

入力・コード・実行バイナリはplan.jsonのハッシュで固定。旧src・bin/release・採用版・以前の計画や対局ファイルを変更しない。新規ランナーは既存４局ランナーを基に、空履歴と初手固定の厳格な受付を追加したもの。
