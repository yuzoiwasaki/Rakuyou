# 50点以内の受け優先に使う候補分類の試作

## 状態と目的

`experiment/defense-preference-within50` の診断用試作。[合意した選択方式](defense-preference-within50.md)を維持し、受けには守備配置の改善も含める。同じ深さの最初の候補評価で50点以内かを判断し、一段深い確認は追加しない。

今回自動化したのは、盤面と合法手から候補手に暫定的な役割を付ける部分。評価値には加点・減点しない。エンジン本体・定跡・普段の実行ファイルは変更しない。中盤・新たな仕掛けの開始の判定は未実装で、対局へは組み込んでいない。

## 分類方法

ネイティブの合法手を列挙し、打ち歩詰めを明示的に除く。移動先や局面固有のUSI手をハードコードしない。

- **王手への応手**：局面が王手なら全て別枠とし、優先選択の対象にしない。
- **戦術的な手**：捕獲・成り・王手をかける手は別枠。必要な取り返しを受け候補へ置き換えない。
- **侵入口を塞ぐ候補**：自玉の前方１〜２段・左右２筋以内の、相手の利きがある空きマスへ駒を置く。着手後に味方の支えがあり、味方の利き数が相手以上であることを求める。
- **守備配置の改善候補**：玉から縦横２マス以内へ移動・投入する金銀が、玉前方１〜２段の味方金銀への新しい支えを作る。動いた金銀がピンされている場合は、この理由では受けにしない。
- **攻めの候補**：仮に相手がパスした場合に、新たな相手駒を合法かつSEE非負の捕獲で取れるようになる手。新たな標的の有無を着手前後で比較する。実際に相手がパスする、あるいは取りが強制されるという意味ではない。
- 受けの条件と攻めの条件を両方満たす手は**攻防兼用**として保留。その他は**未判定**。玉の静かな移動は受けと決めつけない。

受け候補にはさらに、着手直後にその駒を相手が合法に取ってSEE正になる手があれば、受けのラベルを付けない。支えの数だけでは「歩で銀を取られて駒損する手」も塞ぐ手になってしまったための除外条件である。攻めのラベルはこの条件で消さない。△８六歩のような歩の提供も攻めを始める手になり得るからである。

これは候補分類の近似であり、SEEは盤全体の戦術を解いていない。侵入口の支えの数には幾何的な利きを使い、金銀の支えを増やすことも他の守備を失わない保証にはならない。安全や戦略的な意図を証明する分類ではない。

## 具体例

| 局面と手 | 分類 | 理由 |
| --- | --- | --- |
| 最新50手目の△６四歩打 | 受け | 飛車の利きが通る空きマスを、支えのある歩で塞ぐ |
| 同じ局面の△４三金 | 受け | ５四の銀への新しい支えを作る |
| 同じ局面の△８六歩 | 攻め | ８七の歩への新しい取りを作る。歩を取られることだけで除外しない |
| 同じ局面の△７一玉 | 未判定 | 玉の静かな移動を受けと決めつけない |
| 同じ局面の△３三桂 | 未判定 | この試作の受け・直接的な取りの条件では説明できない |
| 角の取り返しの△３二角×２二 | 戦術的な手 | 捕獲なので通常の選択を維持 |
| 以前の48手目の△４三金 | 未判定 | 同じ移動でも、新たに支える前方の金銀がない |

最新50手目では△５三銀〜６四、△６三銀〜６四も受け候補になった。後者の銀は飛車にピンされているので５三銀への支えは理由にせず、支えのある遮断としてのみ分類する。候補に入ることと、よい受けであることは分けて扱う。

別の局面の△５三銀〜４四は、支えの数だけなら受けに入ったが、相手の歩で銀を取るSEEが正になるため除外した。この例と△８六歩の攻めラベルの維持を回帰テストにした。

## 分類の検査

12局面・884手を列挙した内訳：受け20、攻め218、攻防兼用9、未判定585、戦術的な手43、王手への応手9。これは分類数であり、正解率ではない。全手に人間の正解ラベルを付けたわけではない。

既存の50点選択テストと合わせて８テストが通過した。確認範囲は以下のとおり。

- 上表の代表例、必要な取り返し、王手中の全応手。
- ピンされた銀の支えを加えないこと。
- 支えがあっても駒損になる遮断と、攻めのための歩の提供の区別。
- 全12局面について、実手順と保存SFENの一致、先後反転による役割・理由の対応。
- 自動ラベルを50点選択器へ渡した際の50点／51点境界。境界検査の評価値は人工値であり、実際の探索で切り替えが起きた例ではない。

## 自動ラベルを使った探索試験

全て凍結main `5ecd314`、Shin ON/support10/D10、1スレッド、512MB、定跡OFF。固定深さ18が完了した値で１回だけ判断する。

### 最新50手目

前の候補集合へ新しく拾った２種類の△６四銀を加え、８候補を同一のMultiPV探索で比較した。

| 手 | 後手評価 |
| --- | ---: |
| △６四歩打 | −140 |
| △８六歩 | −159 |
| △１五歩 | −184 |
| △３三角 | −221 |
| △３三桂 | −250 |
| △４三金 | −259 |
| △６三銀〜６四 | −459 |
| △５三銀〜６四 | −806 |

最上位が受けのため切り替えなし。新しく受け候補に入った銀の手も、最上位から50点を超えて離れており選ばれなかった。候補集合を増やすと探索経路も変わるため、前回と数値が異なることを性能の変化とは解釈しない。

### 同じ棋譜の直前３局面

44・46・48手目を追加した。今度は候補手を指定せず、全合法手からMultiPV8で上位８手を読む。自動分類は全合法手に行うが、点差判定に使うのはこの上位８手の値だけ。より深い確認は行わない。

| 局面 | 最上位 | 後手評価 | 分類と選択 |
| --- | --- | ---: | --- |
| 44手目 | △５五歩 | −73 | 未判定。変更なし |
| 46手目 | △５四銀打 | −163 | 攻防兼用。変更なし |
| 48手目 | △２二角×４四 | −134 | 戦術的な手。変更なし |

４局面ともルールによる切り替えは０件。選択結果が変わっていないため、比較対局は行っていない。32本のPVはネイティブで全手順の合法性（打ち歩詰めを含む）を確認した。

直前３局面は候補分類を確認するオフラインの対照であり、「仕掛け前」と自動判断できた例ではない。上位８手の外の受けを発見できない場合もあるため、この探索方式をそのまま一般の選択器に採用していない。

## 判断と残る課題

局面固有の手のリストを使わず、検討対象の６四歩打と４三金を拾えたことは進展。ただし別の形の４三金や３三桂などを取り逃し、攻防兼用も保留にしている。正解率や棋力改善は未確認。

この段階では分類の診断用として保存する。中盤・仕掛け前の判定、受け候補の拾い漏れと攻防兼用の扱いを確認する前に、通常対局へ組み込まない。既存評価への加点、50点幅の拡大、再確認探索の追加は行わない。

python3 -m unittest test.analysis.test_defense_move test.analysis.test_defense_preference

  --output results/defense-move-classification/classification.json

  --engine results/main-white-20261128-two/runtime/bin/match \
  --output results/defense-move-classification/adjacent-search18.json
