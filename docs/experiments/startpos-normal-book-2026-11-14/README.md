# 通常側だけ定跡ON：初期局面から先後２局

通常Rakuyouが定跡を使う相手に対して、採用版の駒組みが自然かを見る。採用版は新米長玉ON/support10/D10・定跡OFF。相手は従来の固定通常Rakuyou、新米長玉OFF/support0/D0・定跡ON。先後を入れ替えて１局ずつ、初期局面から開始する。

通常側は既存book.binを20手目まで参照し、登録のない局面では探索する。絞り込みは既定値（NarrowBook/TinyBook=false、先後の最低定跡評価−300）。定跡候補は既存のランダム選択なので、同じ棋譜の再現や前回との厳密な対比較は目的にしない。採用版の最初の一手は既存仕様の▲４八玉／△６二玉、その後は探索。

双方とも深さ15上限・秒読み10秒・1スレッド・Hash64・Ponder OFF、最大256手。エンジンは毎局新規起動し実験用RAKUYOU環境変数を除去。旧src・実行ファイル・以前の計画や棋譜は変更していない。

## 実行

リポジトリ直下で：

```sh
caffeinate -i python3 -u docs/experiments/startpos-normal-book-2026-11-14/match.py run
```

準備・動作確認済み、本対局は未実行。目安１時間前後、両局最大手数なら約85分＋処理時間。Ctrl+Cを１回押すと現在の局が終わってから停止し、同じコマンドで残りを再開できる。２回目のCtrl+Cや失敗した局は自動再試行しない。エラー時は記録を残して確認する。prepare/preflightを再実行しない。

別ターミナルから進捗確認（１局終了ごとに更新）：

```sh
cat results/teatsui-startpos-normal-book-2026-11-14/summary.txt
```

終了後にCompleted 2/2以下を共有する。勝率の証明や前回との合算ではなく、勝敗を問わず明確な序盤の受け不足・無理な前進・駒の遊びを優先して確認する。曖昧な問題は深追いしない。

## 検証

11項目のテスト成功。通常側の20手以内に限り定跡手を許可し、採用側や上限後の定跡手を拒否する。定跡手の記録は探索深さ・探索時間の検査と分離する（定跡評価は今回の探索評価ではない）。通常探索への移行・初手固定・先後・再開・失敗停止も検査。

実エンジンの８回の接続確認は、定跡手３回、深さ３の探索３回、採用側初手固定２回。全てネイティブ判定器で合法性確認。初期局面の通常側が定跡を利用したことも確認。定跡ONでも常に定跡が続くとは限らないため、本対局後に実際の利用手数を集計する。設定・入力・コードはローカルplan.jsonのハッシュで固定する。
