# 既存データを使う小規模な追加学習：実装調査と実験案

2026年10月11日、ソース基準 `4016d24`。今回行ったのはソース調査、
ローカルデータの集計、ファイルのハッシュ確認、計画の記録だけである。
ビルド、探索、対局、教師バイナリ生成、学習は実行していない。

## 結論

現行 `params.bin` を出発点とする追加学習は**変更を加えれば可能**である。
ただし既存 `--learn` は新規学習用で、起動時に読み込んだ評価パラメータを
学習開始時に消去する。既存CLIをそのまま使う方法は採らない。

配布用 `params.bin` は学習用の分解前パラメータや最適化履歴を保持しない。
元の学習状態を完全に再開することと、現在の評価を維持して差分を学ぶことは
区別する。前者のチェックポイントはローカルでは見つからなかった。
後者は、現行テーブルを固定ベースにし、ゼロから始める小さな差分を加える
方式で実現できる。最初は既存の手番評価3係数だけを対象とする実装・数値実験を
推奨する。棋力向上の判定や広範囲の評価学習は後段に分ける。

先手▲７六歩6局面、後手v2の11局面、共通ファイル
`books/shin-yonenaga-book-v1.txt`、`BookMaxPly20`、初手玉移動、
`ShinYonenagaGyoku` と25cpの序盤評価補正は維持する。

## データ形式

### 棋譜DB

[GameDatabase](../../src/gamedb.h) / [reader](../../src/gamedb.cc) は
`kifu_db.txt` の2行1局形式を読む。UTF-8、平手初期局面からの棋譜である。

```text
<整数ID> <日付> <先手名> <後手名> <結果0/1/2> <着手数> <棋戦名> <戦型名>
<CSA着手6文字を連結した列>
```

結果は0=引き分け、1=先手勝ち、2=後手勝ち。着手列は `7776FU3334FU...`
のように先後符号を含まない6文字単位。USIの移動、成り、駒打ちは盤面を再生して
CSAに変換する必要がある。`resign` / `win` は着手に含めない。
ヘッダー項目は空白区切りであり、空白を含む名前等は別途整理が必要。

評価学習側は「七大棋戦＋順位戦だけ」のフィルターをONにするため、自己対局を
そのまま登録すると読まれない。棋戦名の偽装ではなく、このフィルターを設定可能に
するか、実験用readerを追加する。readerは途中の不正着手で切れた棋譜も成功として
返すため、変換時に全着手数・合法性・結果の検証を必須とする。
さらに学習側の `winner = black_win ? black : white` は引き分けを後手勝ちに
扱ってしまう。結果を明示的に分岐し、未確定結果は勝敗損失だけをマスクする必要がある。
reader自体の棋戦フィルター既定値はOFFだが、評価学習が明示的にONへ変更している。
対象名は竜王戦・名人戦・王位戦・王座戦・棋王戦・王将戦・棋聖戦・順位戦の8つで、
全プロ棋戦を許すものではない。評価学習CLIからこの制限を解除する引数はない。

### 教師局面バイナリ

[TeacherPosition](../../src/teacher_data.h) は
`HuffmanCode`（32byte、256bitの盤面・持駒・手番）、`Move`（内部32bit表現）、
`Score`（整数評価値）の構造体。`fwrite(sizeof(TeacherPosition))` の生ダンプで、
ヘッダーや版番号はない。現行型から40byteが見込まれるが、converterでは
`sizeof` / offset / endianを実際の対象ビルドで確認する。
他エンジンの同名圧縮形式やUSI文字列と互換とは仮定しない。
局面の履歴・千日手回数・探索条件は格納されない。

| ファイル | `score` の意味 | 消費側 |
| --- | --- | --- |
| `teacher_positions.bin` | そのルートの手番側cp | 静止探索の評価を探索教師に近づけるRootStrap。`move` はこの損失では使われない |
| `teacher_games.bin` | 手番側が最終勝者なら `+31000`、敗者なら `-31000` | 静的評価の勝敗回帰。通常cpを入れてはいけない |
| `pv_data.bin` | 別の `TeacherPv` 形式 | 生成・readerはあるが、現行 `LearnEvaluationParameters` では読まれない |

`TeacherPv` はHuffman局面、float進行度、結果enum、int長さ、
`kMoveNone` で区切った可変長の内部Move列を持つ。既存探索JSONのPVを
ここへ変換するだけでは現在のtrainerの入力にはならない。

既存generatorは教師局面3,000万件、教師対局300万局を生成する設定である。
今回は既存データの再利用を優先し、generatorは起動しない。

### 評価バイナリと学習状態

[EvalParameters](../../src/evaluation.h) は駒価値、KP、PP、利き、玉安全度、
飛び駒、手番の展開済み整数テーブル。`kFvScale=65536`。
KPの第4成分は評価点ではなく**進行度重み**であり、他の項目の第4成分とは意味が違う。
`params.bin` はこの構造体をそのまま保存・読み込む。

[ExtendedParams](../../src/learning.h) はfloatの絶対・相対特徴、共有特徴を持ち、
`EachKP` / `EachPP` 等で合算して `CopyParams` が探索用テーブルへ変換する。
駒価値の段階別成分も展開・平均化される。整数化と特徴の合算により、配布テーブルから
元の特徴分解を一意に復元できない。従って `params.bin` の単純なmemcpyや、
`ReadParametersFromFile` を学習初期化の後に追加するだけでは継続学習にならない。

継続方式の選択肢は次のとおり。

1. 元の `ExtendedParams` を保存したcheckpointがあれば読み込む。
   厳密な再開にはRMSprop累積値、平均化累積値と更新数、乱数状態、入力版も必要。
   ローカルの `bin/` / `results/` / `local/` には見当たらない。
2. 展開済みテーブルを近似分解する。復元誤差・対称性・正則化の問題が増えるため初回は保留。
3. **固定ベース＋ゼロ初期値の差分**を学ぶ。ゼロ差分時に現在の評価を完全に維持できる。
   初回はこの方式を採る。

一般化した差分方式では `base + Compile(delta)` を整数テーブルに反映し、
ベースの駒価値・進行度を保持する。既存 `CopyParams` は駒価値と進行度も書くため、
そのまま差分用には呼べない。正則化も元の評価をゼロへ縮めるのではなく差分に掛ける。
今回の手番3係数だけなら、巨大な `ExtendedParams` / 全テーブル勾配を作らずに済む。

- `records[].analysis` の評価はその着手**前**の手番側。着手後局面を教師ルートにしない。

- `source=fixed_opening/book/dedicated_book` の値は探索教師にしない。
  定跡表示のdepth32/cp0は探索で確定した評価ではない。
- boundは構造化フィールドだけでなく保存された `raw` から確認する。

- ON教師のcpには固定25cp補正が含まれる。学習する予測値にも同じ固定補正を含める。
  OFF教師をON予測へ混ぜたり、一律25cpを教師から引いたりしない。
  RootStrapの静止探索では末端とルートの補正が違い得るため、末端評価を扱う必要がある。
- 過去の自己対局ではShin側ON、通常側OFF。通常側のcpをON教師として使わない。
  古い実行ファイルのハッシュが記録されていないrunは、レポートから由来を補い、
  現行データとの一致が確認できないものを主学習集合から外す。
- 1局内の相関、run内の状態持越し、長い共通prefix、SFEN合流がある。
  ランダムな局面単位のtrain/test分割は避ける。
- 既存深探索は定跡選択のために選別された序盤集合であり、全般的棋力のtestではない。
  同じエンジンの探索cpを教師にする実験は蒸留で、棋力向上を自動的に保証しない。

## 必要な変更と実装順

以下は次回以降の実装案であり、今回ソースは変更していない。

1. **データ監査・変換**：JSON→版付きの実験用JSONL＋manifest。
   ルートSFEN、USI着手、手番、cp、depth、PV、ON/OFF、run/game/ply、元ファイルSHA、
   元バイナリ・評価・定跡の由来、除外理由、分割groupを保持する。
   C++側の既存USI parser、合法手判定、Huffman codecを用いて照合する。
   最初はJSONLの直接readerでよく、40byteの生ダンプを必須にしない。
2. **安全な実験入口**：既存 `--learn` とは別に入力、固定ベース、出力先、
   seed、1スレッド、batch、更新上限、損失、学習対象を明示する入口を設ける。
   dry-runは入力検証・件数・メモリ見積りだけ。空集合、小さすぎる集合、
   壊れた入力、出力と入力の同一実体を更新前に拒否する。
   既存バッチ処理は件数未満で範囲外になるため、そのまま流用しない。
3. **固定ベースと差分**：初回は `tempo[0..2]` のfloat差分3つのみ。
   `tempo[3]` とその他の全テーブルを保持する。整数化は出力時に行い、
   float状態、最適化状態、平均化状態、seed、入力hashをcheckpointに保存する。
   小規模実験は最終更新でも保存し、既存の100更新間隔に依存しない。
4. **探索cp損失だけを選べるようにする**：既存RootStrap CLIは棋譜学習も必須なので、
   独立した探索教師モードが必要。勝敗、不一致、進行度、確率の学習は初回OFF。
5. **数値・保存・評価の検証**：ゼロ差分、符号、進行度、差分以外のbyte一致、
   読み戻し、損失と勾配の有限差分検査を先に通す。

既存RootStrapは `c*(y-t)^2` を表示する一方、勾配では
`c*gain*(y-t)*derivative_of_sigmoid(gain*y)` を使用している。
`y=sigmoid(gain*score)` なので、この式はその二乗損失の厳密な導関数
`2*c*gain*(y-t)*y*(1-y)` と一致しない。
根拠：[RootStrap](../../src/learning.cc) と [math](../../src/common/math.h)。
新実験では目的関数と勾配を明示して有限差分で確認する。
既存実装全体を今回修正することや、係数だけを変えて流用することはしない。

学習用全配列は複数の `ExtendedParams`、スレッドごとの `Gradient`、
64MBの置換表を伴う。少量の教師でも全配列のメモリは減らない。
既存trainer全体の最大RSS・実行時間は今回未測定。
初回の手番3係数方式でもベースの259MBテーブルと探索メモリが必要なので、
dry-runと短い検証で実測してから更新へ進む。

## 最初の実験案

目的は「現行評価を保持して既存探索教師から小さな差分を学び、
分離保存・再読込・検証できる」こと。手番3係数では右玉の安全度や銀の配置を
直接学べないため、これを本格的な強化実験とは扱わない。

### 0：更新なしの検証

- 独立ディレクトリ `results/learning-pilot/<id>/` を用意し、
  現行データの検証済みコピーを読み込む。入力は読取り専用、出力は別名。
  既存 `bin/release` を作り直さず、実験用バイナリも別パスに作る。
- データsplitと除外を確定し、全着手を合法性検証する。
  ゼロ差分で出力したparamsのSHAが固定ベースと一致することを必須とする。
- 初期局面、先後右玉、左戻り、駒打ち、成り、中終盤、反復候補で
  ON/OFFそれぞれ評価一致、差分評価一致、進行度一致を確認する。
  固定seedでもZobristの起動時乱数等があるため完全な探索再現性は別に確認する。

### 1：上限を決めた差分学習

| 設定 | 初回案 |
| --- | --- |
| 教師 | 由来を確認できた既存depth15のShin-ON探索cp。24〜80手目を中心に、両色・引き分け局を含め、後手draw層も別集計する |
| 抽出 | 1局最大8ルート、同一board/hands/turnは上限1件、cp絶対値1,000以下。反復履歴・mate・bound等を除外 |
| 分割 | run単位を基本にtrain1,024／validation256／test256ルートを上限とする。共通prefix・SFENを監査し、跨ぐ重複を除外。足りなければ縮小して件数を記録 |
| 深探索184候補 | 重複監査後、診断用に保持。trainとの重複は除外・別記し、独立test件数に足さない |
| 学習対象 | ベースに加える手番3係数だけ。駒価値・KP/PP・玉安全度・利き・進行度・固定25cp補正を固定 |
| 損失 | RootStrap型のシグモイド二乗誤差（gain=1/600）＋差分へのL2。新実験で勾配を検証 |
| 更新 | 1スレッド、seed固定、batch128以下、最大20更新。RMSpropの各更新上限0.25cp、係数差分の絶対上限5cp |
| 保存・ログ | 更新0/5/10/20でfloat差分、整数params、optimizer、train/validation損失、cp誤差、差分、時間、RSS、manifestを分離保存 |
| 選択 | validationで候補を選び、testは最後に一度だけ評価。悪化・変化なしなら据置 |

L2の係数と勾配の総和／平均の扱いは実装時に式と単位を確定してmanifestへ記す。
既存の8,000／80,000バッチ用係数をそのまま持ち込まない。
静止探索のPV末端を予測対象とし、rootの教師と同じ手番へ符号を揃える。
初回はベースの静止探索で選んだ末端を固定して勾配検証・学習を行い、
更新後の静止探索を別途再評価する。これによりPVの切替と数値微分を分ける。
末端評価をルートに戻すときは手数による符号反転が必要であり、手番係数の勾配も
単に常時 `+1/2` とはしない。

上限超過、非有限値、異常な評価、進行度／固定テーブルの差分、入力混在で停止する。
20更新で閉じ、自動的な100更新・大規模化・再探索・対局追加はしない。
検証改善があっても現行 `bin/params.bin` への昇格は行わない。

### 2：その後の棋力実験

数値と保存の検証が通った後に別計画として、現行評価を対照、実験評価を試験側にし、
同じ共通定跡・ON・深さ・スレッド数で両色を含む外部比較を行う。
既存定跡試験の勝率を直接対照にしない。100局程度は重大な劣化の探索用で、
小さな強化の証明には使わない。曖昧なら据置。
実用的な配置学習へ進む場合は、差分方式のまま既存relative-KP等の対象を一つだけ
広げ、汎用局面の保持・両色・終盤の退行を別に評価する。
