# 先手新米長玉定跡への移行と最初の検証方針

後手は[v2を第一運用版として固定](2026-10-03-v2-bounded-white-improvement-cycle.md)
し、今回の改善サイクルを終了した。先手は初手▲４八玉 `5i4h` から
独立に設計する。後手の手順を反転して登録せず、通常側の実際の応手と
玉の配置・駒組み・中盤へのつながりを確認する。
初版は入口集計と計画整理まで。その後、ユーザーの着手依頼により
[先手300局の監査・分岐レビューと入口３局面の深さ24解析](2026-10-03-black-300-game-branch-review.md)
を実施した。先手定跡の実装・追加対局はまだ行っていない。
継続検証で通常側応手と深さ28再確認を含む５探索を同レビューへ追記済み。
現在は▲２六歩先行型を試験版の第一検討候補とし、△４二銀・△３二金への
先手準備を次に確認する。以下は最初の作業計画で、最新の順番はレビュー末尾を参照。
ユーザーの希望により、先手玉を１～４筋に残す構想を優先し、早い玉戻りは
安易に定跡へ固定しない。戻る手自体は禁止せず、25cp補正は維持する。

## 既存の先手300局を出発点にする

Git管理外 `results/` の以下の６ファイルは各100局の先後交代実行。
各50局の先手新米長玉を抽出した。初版では勝敗・序盤prefix・着手sourceを
再集計。その後のレビューで全600局の記録・勝敗・集計を照合し、対象の先手300局を
盤面・持駒・手番で再生した。全着手の独立合法性・正式な反復裁定ではない。

v1/v2は後手定跡で、先手では専用定跡着手が０。先手成績の差を
v1/v2の効果とはみなさない。標準定跡ON/OFF、古い実行時バイナリや
先後交代による探索状態の違いを確認してから深掘りし、合算勝率を
現在の先手固定基準の代わりにしない。バイナリハッシュが自動記録
されない旧JSONは、現在の実行ファイルと同一だったと断定しない。

入口の事実：

- 全300局で初手▲４八玉に△３四歩 `3c3d`。他の２手目を否定する根拠ではない。
- `5i4h 3c3d 7g7f 7a6b`（△６二銀）が162局。
- `5i4h 3c3d 7g7f 8b4b`（△４二飛）が82局。
- `5i4h 3c3d 7g7f 7a6b 2g2f 6c6d` が94局、
  同５手目からの△３二金 `4a3b` が47局。
- 四間飛車側の `5i4h 3c3d 7g7f 8b4b 9g9f 4c4d` が30局。

△６二銀と△４二飛の両方を入口にし、居飛車系／振り飛車系への
先手新米長玉の駒組みを分けて考える。

## 次の作業順

1. 既存300局を実行別に監査・局面合流で整理し、２つの主な入口の
   勝ち／負けの代表例、後手の標準定跡の退出点、玉の移動を確認する。
   序盤と中盤の問題を分け、頻出という理由だけでは登録しない。
2. 最初の深い探索は下記３局面以内。新米長玉ONで先手候補を無制限に
   読み、有望手に対する通常側の直接応手はOFFで確認する。
   まず深さ24・MultiPV5・１スレッド/Hash512MB・定跡なし・局面ごと
   新規プロセス。近接候補だけ深さ28へ進め、順位変化を明記する。
3. 小さい先手試験定跡を別ファイルで作り、未登録応手は探索へ抜ける。
   現在のビルダーはWhite専用なので、Blackを明示指定する対応と
   回帰テストが必要。後手運用版は上書きしない。
4. 新しい先手固定・専用定跡なしの基準と試験版を、同一バイナリ・
   通常側標準定跡ON・深さ15等で比較する。長い対局はユーザーが外部で
   実行する。旧先後交代50局の合計だけで効果を判定しない。

### 最初の探索候補（深さ24の初回解析済み）

| 局面のUSI指し手列 | 解析側 | 比較の焦点 |
|---|---|---|
| `5i4h 3c3d` | 先手ON | ▲７六歩 `7g7f` と▲２六歩 `2g2f` を含む無制限候補。根の方針を固定する価値があるか |
| `5i4h 3c3d 7g7f 7a6b` | 先手ON | 実戦の▲２六歩を含む無制限候補。居飛車系の骨格と玉・金銀配置への接続 |
| `5i4h 3c3d 7g7f 8b4b` | 先手ON | 実戦の▲９六歩 `9g9f`、▲２六歩等を含む無制限候補。対四間飛車の骨格 |

いずれも候補を限定しない。首位が実戦手と近いなら無理に差分を作らず、
必要な枝だけ登録する。全評価値は手番側、ON/OFFや深さの異なる数値を
差し引かない。勝ち越しは長期目標であり、探索を無期限に広げる条件にはしない。
