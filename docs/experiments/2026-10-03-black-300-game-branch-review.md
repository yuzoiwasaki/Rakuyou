入力は[着手方針](2026-10-03-black-book-start-plan.md)に一覧とSHA-256を

新米長玉側のOwnBook・専用定跡設定、実行時期・探索状態の経歴は異なる。
当時のバイナリハッシュ自動記録がないため現在のバイナリとの同一性は断定しない。

`tools/review_black_runs.py` を追加した。全６ファイルでerrors０、100局完了。
全600局のsummary再計算、pair番号・先後交代、recordsと指し手配列、着手source集計、
投了側と勝者、256手分けとresultを照合した。さらに対象の先手300局を
盤面・持駒・手番で再生し、駒所有・捕獲・成り・持駒に矛盾がないことを確認した。
これは全着手の独立合法性や連続王手千日手裁定の検証ではない。


テストは生データ・エンジンに依存せず、正常データ、pair不整合、結果不整合、
source集計不整合、引き分けの半点処理の５件を確認する。
局番号は元100局ファイル内の１始まり配列番号（先手新米長玉は奇数番）。
旧JSONに独立したgame_numberはないため、pair/game_in_pairも出力する。

### 判断と次の限定的な構想検証

1. ６枝版は候補として保存するが、運用採用は保留。今回の結果は基準と
   ほぼ同水準で、条件枝の棋力効果は未確認。７局面固定版も採用保留を維持。
2. 入口の▲７六歩／▲２六歩の小修正を繰り返す前に、次の構想候補である
   **▲３八銀・▲６八銀から金銀を整える別骨格**を少数局面で比較する。
   既存 `5i4h 3c3d` の無制限ON・深さ24/MultiPV5では
   ▲７六歩／▲２六歩−121、▲３八銀−129（先手手番側）。
   同一探索内の８cp差は▲３八銀を比較候補に残す根拠だが、実戦成績の保証でない。
   ▲６八銀の優劣はこの数字から判断しない。
3. 角交換を許容し、右側の玉・金銀・飛車をバランスよく配置する構想も
   **未検証の仮説**として調べる。自分から交換する形と、相手の交換を受ける形を
   分け、角打ちの隙・逃げ道・仕掛けへの備えを確認する。
   初手▲４八玉は玉の位置を早く決めるため、先手の一手分だけで安全とは言わない。
   既存右玉の知見は参考にするが、玉配置だけで定跡の合流・成立とは扱わない。
4. 相手の戦型は強制していない。今回r1でも▲７六歩に△４二飛が15局ある。
   銀先行なら居飛車を選びやすいという見立てはまだ仮説で、標準定跡での応手と
   OFF・定跡なし探索での応手を別に確認する。居飛車／振り飛車の両方を除外しない。
5. 次段階は根 `5i4h 3c3d` の銀先行候補、通常側の直接応手、成立しそうな
   角交換前後の配置、の順に絞る。深さ24程度の入口比較を起点とし、
   有望枝にだけ深い再確認・短い試験定跡・外部対局へ進むことを提案する。
   結論が弱ければ先手専用定跡なしを暫定運用とする区切りも残す。
   後手への流用は配置の考え方の候補であり、手番・整備の間に合い方を別途検証する。
   後手運用v2は今回変更しない。
