# 合法な侵入手と受けの成否の診断

## 状態

評価関数へ組み込む前のオフライン診断。前の３つの幾何的な補正はユーザー判断で不採用とし、既定値0の実験記録として残す。この診断ではエンジン本体・定跡・探索を変更していない。作業と記録は独立評価用の `experiment/king-approach-defense` に保存する。

目的は、侵入先の利きの数ではなく、合法に侵入された後に取れるか、その取り返しが駒損か、局面全体を読んでも取る手がよいかを分けて調べること。

## 方法と範囲

相手玉の前方１〜３段・左右２筋に着地する合法手を列挙する。桂打ちの▲４五桂も対象にするため３段まで含めた。駒打ちと盤上の駒の進出・捕獲を区別せず列挙するが、これは侵入候補の幾何的な抽出範囲であり、全てが有効な攻めという意味ではない。玉の後方・側面や、離れた場所からの攻めは範囲外。

各候補について以下を記録する。

1. 侵入手のSEE（同一地点での駒交換損得の近似）。
2. 直後にその駒を取る合法手と、それぞれのSEE。ピンされた駒による違法な捕獲は除く。
3. 事前指定した注目手に対し、応手無制限の探索と、初手だけ直接捕獲に限定した探索。以降は通常探索する。
4. 侵入前の局面でも候補手無指定で探索し、注目した侵入が有力な手か、別の攻めがあるかを見る。

打ち歩詰めは明示的に除外する。ネイティブの基本合法手リストだけでは除外されないため、歩打ち後に王手かつ合法応手なしなら除外する。診断で扱うのは合法な局面からの手であり、局面履歴の検証でもこの条件を使う。

SEEの後続交換は近似であり、盤全体の攻め合いや守備の薄さを評価しない。「合法な捕獲なし」を「受けなし」とはしない。駒打ちで遮る、逃げる、反撃するなどの受けは無制限探索側に任せる。探索のPVも強制手順や完全な証明ではない。

検索条件は凍結main `5ecd314` の実行ファイル、Shin ON/support10/D10、1スレッド、512MB、定跡OFF、各探索は新規プロセス。基本比較は完了深さ18、52手目の候補比較は深さ20。制限探索と無制限探索では探索木が変わるので、同じ最善手でも数値は一致せず、差を厳密な「捕獲の費用」とは扱わない。

## ６四への侵入を区別できたか

以下のSEEは、侵入後に後手が取る手の視点。

| 局面と先手の侵入 | 直接取る応手 | 取り返しのSEE | 応手無制限の探索・後手視点 |
| --- | --- | ---: | --- |
| 50手目△８六歩の直後に▲６四歩打 | △５三銀×６四／△６三銀×６四 | ＋198 | △６三銀×６四、＋163 |
| △８六歩▲同角△５六歩の後に▲６四歩打 | 同上 | −230 | △５三銀×６四、−173 |
| 50手目△６四歩打の直後に▲６四歩打 | 不可（マスが埋まっている） | — | — |

角が８六へ移動すると６四への利きが加わり、銀で取る交換の損得が変わる。この差は前の３試作の単純な形の指標より具体的に捉えられる。

ただし、SEEが負になった局面でも通常探索は銀で取る手を選んだ。駒損を避けて受けないほうがよい、とは言えない。第２行の直接捕獲限定探索も同じ△５三銀×６四を選ぶが評価は−269であり、無制限探索との差を非捕獲の受けの価値と解釈してはいけない。

## 必要な取り返しと、直接取らない受け

- ６四歩で受けた継続で、▲４五桂×５三成に対する△５二金×５三は合法な捕獲として残る。SEEは＋855、通常探索もこの金での取り返しを選ぶ（後手−148）。この例で必要な取り返しを除外しないことを確認した。
- 交換が進んだ57手目の▲６九飛×６四は王手で、直後に飛車を取る合法手はない。しかし通常探索は△７二金〜６三を選び、王手を遮りながら飛車に当てる。PVはさらに▲４五銀打△６三金×６四▲４五銀×４四と進む。直接取れるかだけでは受けも、その受けに伴う別の損も表せない。
- 50手目△８六歩の直後の▲４五桂打は、△５四銀×４五がSEE−310。それでもこの桂打ち自体は有力とは限らず、通常探索は△８七歩成で反撃する（後手＋397）。「駒損せずに取れない進出」を一律に危険と数えると、この反撃を見落とす。

## 塞ぐ手の反例

△８六歩▲同角まで共通にして、52手目だけを△５六歩と△６四歩打に分けた。

△６四歩打なら▲６四歩打は不可能になり、隣の▲６五歩打にも△６四歩×６五のSEE＋198で対処できる。しかし先手には侵入範囲の外から▲７七桂など別の攻めがある。

同じ52手目の局面から初手だけを指定した深さ20では、後手評価は次のとおり。

| 初手 | 後手評価 |
| --- | ---: |
| △５六歩 | −89 |
| △６四歩打 | −363 |

この深さでは、６筋の入口を塞ぐことと局面全体が改善することが一致しない。侵入手への局所的な受けの成否を、そのまま初手の加点・減点に使うのは早い。単発の比較なので候補手の普遍的な優劣や棋力を主張しない。

## 検証と判断

７局面で125個の侵入候補を列挙した。全ての候補について直接捕獲の合法性とSEEを記録し、注目した９個の合法な侵入には通常探索を行った。25本の得られたPVについて、打ち歩詰めを含め全手順の合法性を確認した。

３つの自動テストを追加して通過した。打ち歩詰め／合法な歩打ち／二歩、ピンによる捕獲不可／ピンがない場合の捕獲可、必要な取り返し、全７局面の先後反転とSEE・捕獲集合の対応、保存SFENと実手順の一致を検証している。

診断としては、６四の交換条件が悪化する段階を区別できた。一方で、局所的に取れない手への反撃、遮断してから取る受け、別方向の攻めという反例も確認できた。評価関数への採用は行わない。さらに使うなら、局所SEEを単純な減点にせず、反撃・非捕獲の受けも含めて調べる必要がある。

## 再現

評価データとOpenMPライブラリは通常の開発手順に従って用意する。診断器は普段の実行ファイルと別にビルドする。

```sh
make legal-entry-test -j2
python3 -m unittest test.analysis.test_legal_entry
python3 tools/analysis/legal_entry_audit.py \
  --engine results/main-white-20261128-two/runtime/bin/match \
  --output results/legal-entry-defense/search18.json
python3 tools/analysis/legal_entry_audit.py --mode parent-comparison --depth 20 \
  --engine results/main-white-20261128-two/runtime/bin/match \
  --output results/legal-entry-defense/before52.json
```

既定入力は `test/analysis/legal_entry_positions.json`。出力はGit管理外の `results/legal-entry-defense/`。実施時の深さ18結果は初期６局面が `search18.json`、追加した52手目の対照１局面が `paired-search18.json` に分かれている。上記の再実行では７局面を１ファイルに保存する。
