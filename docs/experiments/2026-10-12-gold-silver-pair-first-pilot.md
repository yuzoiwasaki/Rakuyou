# 金銀相互連結の初回学習：1特徴・20更新、運用は基準維持

2026年10月12日。既存train36／validation18の固定末端で出現数とL2の単位を確認した後、
現行評価からゼロ差分で20更新を一度だけ実施した。係数の符号は制約していない。
10更新の保存候補はvalidation損失が微改善したが、20更新では悪化した。
この実験は終了し、追加調整・追加学習・検証拡張・現行評価への採用は行わない。

## 特徴と出現数

同じ側の**金と生銀が互いのマスに利き、両端とも玉を除く味方の利き数が敵より多い**
ペアを1回だけ数える。盤全体を対象とし、成銀や成駒の金相当は含めない。
利きは既存エンジンの利き情報を使用し、ピンの追加判定はない。
前線での直接の支えと利きの余裕を扱うが、前進距離、長い連結、攻めの成果、交換価値は扱わない。

| 固定末端 | train36 | validation18 |
| --- | ---: | ---: |
| どちらかに対象ペアあり | 26 | 16 |
| 先手側にあり | 23 | 16 |
| 後手側にあり | 16 | 11 |
| 先後のペア数差が非ゼロ | 18 | 9 |
| 非ゼロの局面が属するrun数 | 16 | 4 |
| 一色の最大ペア数 | 3 | 2 |
| 先後差の最大絶対値 | 2 | 2 |

十分に出現するため、疎さについての相談は不要と判断した。
独立した幾何学的な数え方と実験用native評価器の数が54件すべて一致した。
出現は棋力向上の根拠とはしない。複数局面が同じrunに属する相関は残る。

## 実行前に固定した単位とL2

1特徴に対して序盤／終盤の2係数を学ぶ。単位は**1ペアあたりのcp**で、
差分は `(先手ペア数−後手ペア数)×((1−進行度)×序盤係数＋進行度×終盤係数)`。
手番係数の1/2係数は適用しない。先後への符号変換・進行度は既存の固定末端方式と同じ。

trainだけで測ったゼロ点のデータ勾配は序盤 `−7.95345e−6`、終盤 `−1.43081e−6`。
前回のL2 `1e−4`なら、およそ0.080／0.014cpで同程度の正則化勾配になり、
変化を極小に抑えやすい。今回は**validation損失を見る前にL2を1e−6へ固定**した。
係数上限0.5cpでもL2勾配は5e−7で、初期データ勾配の約6.3%／34.9%。
これはこの特徴の数え方・単位に対する確認であり、結果を見た再調整はしていない。

既存の8座標の目的関数・更新器を使い、最初の2座標だけを有効にした。
残り6座標は入力・勾配・状態すべてゼロのまま。目的は探索教師cpへの平均sigmoid二乗誤差と差分L2。
バッチ最大128（実際36全件）、seed20261011、RMSprop、更新幅上限0.05cp、係数上限±0.5cp、
20更新、移動平均係数を0／5／10／20で保存、局面全体のroot／leaf差上限10cp。
先後・draw層は別に確認するが、drawを勝ちに変換せず、打切りdrawに勝敗損失は付けない。

加点を強制したのではなく、今回の探索教師に対する勾配が正方向への更新を選んだ。
事前の選択条件（整数変化あり、上限内、validationのL2込み損失改善、同値なら早い保存）では
10更新を選択した。運用採用とは別の実験内の候補選択である。
10更新のデータ損失改善は約0.0182%、20更新では約0.0651%悪化。18件での暫定観察に留める。

20更新の平均係数におけるデータ勾配は `−7.92290e−6／−1.41350e−6`、
L2勾配は `+2.42898e−7／+2.16409e−7`（約3.1%／15.3%）。
前回のように正則化とほぼ釣り合って停止した状態ではない。
滑らかな差分モデルの最大絶対差は10更新0.317cp、20更新0.474cpで、小さい変化が中心。
固定末端／rootのnative整数差は**全保存候補・全54局面で最大1cp**、上限10cp内。
20更新ではtrain5/36、validation3/18の固定末端整数評価が変わった。

全体の微改善から後手やdrawにも有効と一般化しない。

## 実装・保存・検証の範囲

この金銀ペア関係は既存の玉周囲テーブルだけには正確に格納できないため、
通常の評価・USI設定は変えず、`make gold-silver-pair-probe` の実験用評価器だけで
読み込んだ現行評価の序盤／終盤成分に差分を加える。
候補は基準SHAと特徴定義に結び付けた**2係数のJSON sidecar**で保存する。
通常の `bin/release` がこのsidecarを読み込めるという意味ではない。
`params.bin` の偽のテーブル書換えや新しい運用フラグは導入していない。

- 独立の数え方との54件一致、ゼロ差分と保存済み評価の完全一致。
- 新規4テストと既存安全度6テストが通過：相互の利き、厳密な利き余裕、玉の除外、成銀除外、
  左右対称・先後反転、負の係数も学べること、20更新上限、保存／復元。
- trainの解析勾配と数値差分、正負のnative摂動を確認。追加探索0、対局0、test局面0。
- 全候補のroot／leafでKP・手番・進行度・対象外の成分が不変、指定したペア残差だけが変化。
- 選択10更新候補を保存値からnative再評価して全54件完全一致。これは静的再生であり再学習ではない。
- 元の57ファイルバックアップを維持し、今回追加の17ファイルだけ別コピーしてSHAと独立性を確認。
- `mutual-pair-learning-attempt-v1.json` により再実行を防止。消して再調整しない。
- 現行release／params／progress／probability／bookと共通定跡17局面のSHAはすべて不変。
  定跡・25cp補正・以前の手番／安全度候補も維持した。

特徴から小さい学習信号と整数変化は得られたが、先後・drawに一貫する効果は見られない。
棋力改善の裏付けはなく、現行評価は維持する。この一回で区切り、結果を材料に次の相談へ進む。
